## 확장 수록 파일 형식 (`medterm_ext.json`)

첫 줄이 `{"meta":{…},` 이고 그 아래 `"entities":[` 에 성분이 한 줄에 하나씩 들어 있습니다(줄 단위로 비교하기 좋게).

`meta`: `name` · `version` · `built_at`(자료 기준일) · `review_status`(`draft`) · `notice` · `grade_legend` · `src_legend` · `sources`(출처 네 곳 R·H·W·A: 이름 · 쓴 것 · `license`(이용 조건 문장) · `license_tag`(화면 배지 글자) · `license_class`(`open` / `attribution` / `pending`) · `credit`(표기할 기관) · 원자료 링크 `rec_url`·`file_urls` · 쓴 파일 `files`) · `counts`(건수) · `atc_names`(쓰인 ATC 1~5단계 분류 영문명) · `files`(입력 파일 기록: 자료 번호, 바이트 수, **SHA-256**, 포털 자료명·등록일·수정일·갱신 주기, **받은 날 `fetched`**) · `fetch_note`(받은 날을 정확히 기록하지 못한 파일이 있을 때의 설명).

`entities[]` 한 줄의 필드:

| 필드 | 뜻 |
|---|---|
| `id` | `MT:VTM:<RxCUI>`(미국 RxNorm 성분) 또는 `MT:KRI:<이름>`(심평원에만 있는 성분). 화면 주소는 `#v-<RxCUI>` · `#k-<이름>` |
| `rxcui` · `label_en` · `alt_en` | RxNorm 번호(없으면 `null`) · 영문 이름 · 영문 동의어 |
| `ko[{n,s,c}]` · `ko_base` · `ko_alias` | 한글 이름 **후보**(`s` 출처 글자, `c` 심평원 품목명 괄호 표기에서 나온 횟수) · 염·수화물 꼬리를 뗀 이름(검색·인식용) · 별칭 |
| `atc` · `atc_src` · `atc_class` | ATC 코드(7자리, 여러 개 가능) · 코드별 출처 글자 · 4단계까지의 분류 |
| `brands_ko` | 상품명 후보(성분 한 가지짜리 품목명의 앞부분을 기계적으로 자른 것, 최대 10개) |
| `kr{items,combo,codes,forms,routes,strengths,n_strengths}` | 심평원 등재 현황: 단일성분 품목 수 · 복합제 품목 수 · 성분코드 수 · 제형 · 투여 경로 · 함량 샘플(≤16) · 함량 가짓수 |
| `hira_codes` | 이 성분이 **단일성분**으로 나오는 심평원 일반명코드 **전체(9자리)** 목록(정렬·중복 없음, 개수는 `kr.codes` 와 같음). 원자료의 행을 되짚는 용도이며 성분을 합치는 열쇠가 아님(아래 "일반명코드를 이렇게 다룹니다") |
| `near[{id,n,r,atc}]` | 이름이 비슷해 확인이 필요한 항목(**자동으로 합치지 않음**) |
| `cand` · `map` · `grade` | 연결 후보 · 연결 규칙과 ATC 일치 단계 · 연결 등급(아래) |
| `src` · `wd` | 자료 출처 글자(R·H·W) · Wikidata 항목 번호(같은 RxCUI 에 여러 개면 번호가 가장 작은 것) |
| `review_status` | 항상 `draft` |

항목마다 이용 조건 문장을 복사해 두지 않습니다. 어느 출처(R·H·W·A)에서 온 항목인지는 `src` · `atc` · `rxcui` · `wd` 로 정해지고, 그 출처의 이용 조건·원자료 링크·받은 날은 `meta.sources` · `meta.files` 에 한 번만 적혀 있습니다. 화면과 `provenance(id)`(`web/js/core.js`)가 이를 풀어서 보여 주며, 출처·이용 조건 표시가 빠진 항목은 자동 점검(`provenanceStats().missing`)이 0 인지 확인합니다.

### 연결 등급

| 등급 | 뜻 | 항목 수 |
|---|---|---|
| a | 이름 일치 + ATC 코드(7자리) 일치 | 873 |
| b | 이름 일치(ATC 근거가 한쪽에 없거나 4단계까지만 일치) | 1,278 |
| c | 후보(이름은 맞으나 ATC가 서로 달라 연결에 쓰지 않음) | 1 |
| d | 미매핑(심평원에만 있는 성분) | 689 |
| `-` | 심평원과 연결되지 않은 RxNorm 성분(ATC 보유) | 717 |

한글 이름은 **추측해서 만들지 않습니다.** 심평원 품목명 괄호 표기에서 많이 쓰인 것이거나 Wikidata 의 한국어 이름만 쓰고, 찾지 못하면 비워 둡니다(화면은 영문 이름 + "확인 필요").

### 매핑 원칙

- 이름이 같거나, 염·수화물·약어 표기 규칙(`build/ext_norm.py`, 규칙표 `docs/염_정규화_규칙표.md`)을 적용해 같아지는 것만 합칩니다. 비슷하기만 한 이름은 `near` 후보로 남기고 **자동으로 합치지 않습니다**.
- 양쪽에 ATC 가 있으면 대조해 a(7자리 일치) · b(4단계까지 일치 또는 한쪽에 근거 없음) · c(ATC 불일치 — 연결에 쓰지 않음)로 나누고, 연결하지 못한 심평원 성분은 d(미매핑)로 둡니다. 추측으로 한글 이름을 채우지 않습니다.
- **복합제는 아직 성분 배열로 분해하지 않았습니다.** 심평원 자료에서 온 2,841개 중 `hira_codes` 가 없는 589개는 복합제 품목에만 나오는 성분 462개와 연결된 등재 품목 정보가 전혀 없는 127개입니다(다음 회차 과제).
- 등급이 실제로 맞는지는 아직 **약사가 판정하지 않았습니다.** 상용 상위 100 성분의 등급 분포는 a 80 · b 8 · d 12 이고, 등급 b 의 정확도는 층화 시트로 따로 재도록 준비했습니다(`docs/약사검수_판정시트_안내.md`). 판정 결과가 나오기 전의 등급은 "자동 연결의 근거 수준"일 뿐 정확도가 아닙니다.

## 최신 승인·임상·화합물 연결 (`medterm_new.json`, v1.3.0)

공개 자료 세 곳을 자동으로 모아 **영문 성분 이름(소문자)** 을 열쇠로 묶은 파일입니다. 핵심·확장 사전의 값은 바꾸지 않고, 화면이 성분 상세·"최신·임상" 탭에서 이름으로 찾아 붙입니다. 한 줄짜리 JSON 입니다.

| 키 | 내용 |
|---|---|
| `meta` | 이름 · `version` · `built_at` · `review_status`(`draft`) · `notice` · `sources`(F·T·P: 이용 조건 문장·배지 글자·표기할 기관·원자료 링크) · `fetched`(받은 날) · `status_legend`·`phase_legend`(상태·단계 풀이) · `counts`(건수) |
| `novel[]` | FDA CDER 신약 승인표 한 건: `d` 승인일 · `y` 연도 · `no` 그해 번호 · `b` 상표 · `g` 성분(영문) · `u` 승인 용도(FDA 영문 표기 그대로) · `k` 조회 이름 · `e` 사전 항목 ID(이름이 **정확히** 같을 때만, 없으면 빈 문자열) |
| `tr{이름}` | 임상시험 요약: `n` 이름이 일치한 등록 건수(`cap` 이 true 면 "n건+" — 1,000건을 넘거나, 이름이 너무 흔해 검색이 넓어 쪽 상한(8쪽)에서 받기를 멈춘 하한값) · 아래 `ph`·`st` 등 요약은 시작이 가장 최근인 최대 1,000건 기준 · `ph` 단계별 건수 · `st` 상태별 건수(`act` 진행 중 · `nyr` 모집 예정 · `done` 완료 · `stop` 중단·철회 · `unk` 미상 — 서로 겹치지 않고 합이 센 건수와 같음) · `ind` 산업체 주관 건수 · `spi` 주관 기관 상위 · `cond` 대상 질환 상위 · `ls` 시작(예정 포함) 가장 늦은 달(만든 날로부터 36개월을 넘는 시작은 입력 오류 가능성이 커서 뺌) · `np` 가장 가까운 주요 완료 예정 달 · `ex[]` 진행·예정 중인 2·3상 시험 예(등록번호·단계·상태·주관·시작·완료 예정·짧은 제목) |
| `ch{이름}` | PubChem 화합물: `cid` · `ik`(InChIKey) · `f` 분자식 · `mw` 분자량 · `t` PubChem 제목 · `how`(`exact` 제목이 이름과 정확히 같음 · `single` 이름 검색 후보가 하나뿐이라 연결 — 제목이 다를 수 있음) |
| `sk{InChIKey앞14자}` | 같은 골격(입체이성질체 등)으로 묶이는 이름들(2개 이상일 때만) |
| `sim{이름}` | PubChem 2D 유사도 0.9 이상인 이웃 중 **사전에 있는 이름**만(없을 수 있음) |
| `ent{이름}` | 이름 → 사전 항목 ID(핵심 `MT:VTM:<RxCUI>` · 확장 `MT:VTM:<RxCUI>` / `MT:KRI:<이름>`) |
| `unq{tr,ch}` | **아직 조회하지 않은 이름**(수집이 이름 끝까지 가지 못했을 때만 들어감). 있으면 화면이 "없다"가 아니라 "아직 조회하지 않았다"고 표시 |

### 세는 방식(오해하기 쉬운 곳)
- **등록 건수**는 ClinicalTrials.gov 에서 그 이름이 시험의 *중재(intervention 이름·다른 이름, 또는 제목+중재 설명)* 에 그대로 들어간 등록을 센 값입니다. **유의어 확장은 끈 검색**입니다(확장을 켜면 chlorotrianisene 이 711건처럼 엉뚱한 시험까지 세어져 건수가 5~15배 부풀려져 v1.3.0 수집 도중 바로잡았습니다). 그 대신 코드명(예: HSK3486)·다른 철자로만 등록된 시험은 빠집니다. 비교약·병용약으로 들어간 시험도 섞일 수 있고, 효능·안전성의 근거가 아닙니다. 등록이 아주 많은 성분은 최근 시작 순 1,000건까지만 세어 `cap` 으로 표시합니다.
- **상태**는 한 시험이 한 상태에만 들어갑니다. 수집 원자료는 진행 중 안에 모집 예정을 포함해 담지만 `new_build.py` 가 `act = act − nyr` 로 겹침을 없앱니다(`act + nyr + done + stop + unk = 센 건수` 를 시험이 확인).
- **시작(예정 포함) 가장 늦은 달**이 빌드한 해로부터 5년을 넘는 값(예: 2099-01 같은 자리표시 날짜)은 버립니다(`counts.start_dates_dropped`).
- **단계**: 0 탐색 · 1 · 1/2 · 2 · 2/3 · 3 · 4(허가 후) · NA(기기·행동 등). 화면의 "가장 앞선 단계"는 NA 를 제외하고 고릅니다.
- **FDA 승인은 미국 기준**이며 국내 허가·급여를 뜻하지 않습니다. 사전과의 연결은 영문 이름이 정확히 같을 때만 합니다(상표·접미(-wuug 등)를 뗀 기본 이름도 함께 대조).
- **화합물 연결**은 PubChem 이름 검색에서 제목이 이름과 정확히 같은 것(`exact`) 또는 후보가 하나뿐인 것(`single`)만 씁니다. 같은 골격·구조 유사는 **구조 정보만으로 이은 참고 정보**이며 같은 계열·같은 효과·대체 가능을 뜻하지 않습니다.

## 국내 제품(품목) 층 (`medterm_kr_products.json`, v1.3.0)

심평원 약가마스터 **의약품표준코드**(15067462, 기준일 2026-08-31)와 **의약품주성분**(15067461, 2025-10-31)으로 만든 국내 제품 목록입니다. 공공누리 제1유형(출처표시). 허가·급여·처방 판단의 근거가 아니며 식약처 ‘허가’와 심평원 ‘등재’는 같은 뜻이 아닙니다.

**제품을 세는 단위**: 같은 `품목기준코드`를 여러 업체·이름이 함께 쓰므로 코드 하나가 제품 하나가 아닙니다. 제품 열쇠는 **(품목기준코드, 품목명, 업체명)** 이고, 이렇게 센 제품은 58,178건(전문 39,669 · 일반 18,509 · 업체 582곳)입니다. 서로 다른 품목기준코드는 48,388개입니다. (확장 수록의 ‘품목 수’는 허가 코드 단위이고 여기의 ‘제품 수’는 코드+이름+업체 단위라 제품 수가 더 많을 수 있습니다.)

| 키 | 내용 |
|---|---|
| `p[]` | 제품 한 건(배열): `[품목기준코드, 품목명, 업체 색인(co), 구분(0 전문·1 일반), 성분 구성 색인(cd; 하나 또는 목록, -1 없음), ATC 색인(atc, -1 없음), 허가년월 YYYYMM, 한약제제 추정 규칙(0 아님·1~4), 규격, 특수관리 색인(sp, -1 없음)]` |

### 화면의 출처 표기

- **모든 화면 맨 아래**: 읽은 출처 이름, "원 기관이 보증하지 않으며 최신이 아닐 수 있고 한글명·상품명은 약사 검수 전 초안", ATC·SNOMED CT 재배포 조건 미확인, 그리고 미국 NLM 이 요청한 **영문 표기 문구**(번역하거나 줄이지 않고 그대로. NLM 이름·로고는 쓰지 않음).
- **데이터·한계 탭의 "출처 표기와 이용 조건"**: NLM 영문 문구와 한국어 풀이, 심평원 공공누리 제1유형 표시 문장(기관명·자료명 날짜·내려받기 안내), Wikidata(CC0), 재배포 조건이 정해지지 않은 자료, 출처별 항목 수.
- **확장 성분 상세의 "출처·이용 조건"**: 출처별 식별자(RxCUI · 일반명코드 · Wikidata Q 번호) · 원자료 링크(새 탭, `noopener noreferrer`) · 이용 조건 배지 · 자료 기준일과 받은 날 · 검수 상태.
- 이 문구는 법률 검토를 거친 것이 아닙니다. 외부에 공개하기 전에 확인해야 합니다. NLM 이용 약관(RxNav 이용 약관, 2026-11-04 확인)은 위 영문 문구를 응용 프로그램에 넣도록 요청하며, 약관의 재배포 범위는 그 페이지에서 확인하지 못했습니다.

### 일반명코드를 이렇게 다룹니다

심평원 일반명코드 9자리 = **6자리 번호 + 투여 구분 1자리(A 내복 · B 주사 · C 외용 · D 기타) + 제형 2자리**입니다(원자료 59,631행 중 투여 구분은 59,619행에서, 제형 2자리는 전 행에서 해당 열과 일치). 앞의 번호는 **성분 식별자가 아닙니다**: 같은 약이 여러 번호를 쓰고(thiopental sodium 은 앞 4자리가 2376 · 3135 · 3942 · 4822), 다른 약이 같은 번호를 씁니다(193801 은 metoclopramide 와 metoprolol, 611901 은 peramivir 와 indacaterol). 그래서

- 코드 앞자리로 성분을 자동으로 합치지 않습니다. `hira_codes` 는 원자료의 행을 되짚는 용도로만 기록합니다.
- 앞 4자리가 둘 이상의 항목에 걸린 60건(`medterm_ext_review_shared_cd.tsv`)에는 같은 성분의 표기 차이(예: cyclosporine / cyclosporin)와 전혀 다른 약이 섞여 있어, 약사가 보고 동의어로 묶을 것만 고르는 **단서 목록**으로만 씁니다.

심평원 두 파일의 기준일은 서로 다릅니다(`meta.files` 에 기록): 의약품주성분은 포털 자료명 날짜 2025-10-31(포털 등록 2025-11-20 · 수정 2026-01-20, 연간 갱신), 의약품표준코드는 파일명 날짜 2026-08-31(포털 등록 2026-09-01 · 수정 2026-09-17, 분기 갱신). 이후의 변경은 담지 못했고, 두 파일의 시점 차이로 성분 목록과 품목 목록이 어긋나는 곳이 있을 수 있습니다. 심평원 ‘등재’는 식약처 ‘허가’와 같은 뜻이 아닙니다.

## 다시 만드는 법 (재현)

원자료는 저장소에 올리지 않습니다(저장소 밖 폴더에 받습니다). 받는 것은 모두 로그인·인증키 없이 받는 **공개 파일**이며, data.go.kr **서비스키는 쓰지 않습니다**. 받은 파일은 신뢰할 수 없는 데이터로 다루고(실행하지 않고 읽기만) 요청에는 일반 사용자 에이전트 이름만 보냅니다.

```
python build/ext_fetch.py --raw <저장소 밖 폴더>                      # RxNav · Wikidata · 데이터포털 공개 파일 (--only rx,wd,hira 로 일부만)
python build/ext_build.py --raw <같은 폴더> --dropped data/medterm_ext_dropped.tsv [--no-net]
python build/make_bundle.py                                           # web/js/medterm-ext-data.js
cd web-react && npm run build
```

v1.3.0 의 두 층(받은 파일은 같은 방식으로 저장소 밖 폴더에 둡니다. 인증키는 쓰지 않습니다):

```
python -I build/new_fetch.py --raw <폴더> --only fda            # FDA 신약 승인표(2021~)
python -I build/new_fetch.py --raw <폴더> --only names          # 핵심·확장·FDA 영문 성분 이름 목록(names.json)

python -I build/new_fetch.py --raw <폴더> --only chem           # PubChem 이름 → CID·InChIKey·분자식·분자량

python -I build/prod_build.py --raw <ext_fetch.py 로 받은 폴더>   # data/medterm_kr_products.json (심평원 파일은 ext 와 같은 폴더)

```

## 알려진 한계

- 한글 이름·상품명은 자동으로 뽑은 후보입니다. 같은 성분에 이름이 여럿이거나 없을 수 있고, 같은 한글 이름이 둘 이상의 성분에 걸리는 경우가 있습니다(검색에는 모두 나오지만 답변 검증에는 쓰지 않습니다).
- 상품명은 품목명의 앞부분을 기계적으로 자른 것이라 틀릴 수 있으며, 허가·판매·급여 여부를 뜻하지 않습니다. 복합제의 상품명은 넣지 않았습니다.
- 심평원 성분 목록에는 있으나 등재 품목·성분코드 정보가 모두 0인 연결이 있습니다(화면은 "연결된 등재 품목 정보 없음"으로 표시).
- 이름 규칙으로만 연결하므로 (염·수화물·약어 표기 차이는 맞추지만) 서로 다른 성분을 잘못 묶었거나 같은 성분을 못 묶은 곳이 있을 수 있습니다. 약사 검수 전입니다(검토 우선 목록: `medterm_ext_review.tsv`).
- 확장 수록에는 제형·용량(VMP)과 제품(AMP)이 없고, 단위용량 검사를 하지 않습니다. CLI(`bin/medterm.mjs`)와 예전 화면(`web/index.html`)은 핵심 사전만 씁니다.
- 외부에 공개하기 전에 ATC·SNOMED CT 의 재배포 조건을 확인해야 합니다. 확장 수록 3,558개 중 2,882개(81%)가 ATC 코드나 분류 이름을 가지고 있어 결정이 필요합니다.
- 심평원 일반명(15067461) 목록의 이름은 약 90%가 영문입니다(한글이 들어간 이름은 7,431개 중 703개). 식약처 성분명과 **한글 정확일치**로 대응률을 재는 방식은 맞지 않아, 영문·한글을 나누어 대조하는 도구(`tools/compare_mfds_names.py`)를 만들었습니다. 이 도구는 시험용 가짜 파일로만 검증했고, 실제 식약처 파일(공공데이터포털 15098095)로는 아직 돌리지 않았습니다.
- 연결 등급의 정확도(약사 판정 일치율·κ)는 아직 재지 않았습니다. 판정 시트와 계산 도구만 준비되어 있고, 실제 판정값은 없습니다.
- (v1.3.0) **FDA 신약은 미국 기준**이고 국내 허가·급여와 무관합니다. 임상 건수는 이름이 *중재*에 그대로 든 등록 수이며(유의어 확장 없음 — 코드명으로만 등록된 시험은 빠짐 · 비교약·병용약 포함 가능 · 효능 근거 아님) 상한 1,000건입니다. 화합물 연결은 이름 검색 결과라 `single`(후보 하나뿐) 연결은 제목이 다를 수 있습니다.
- (v1.3.0) **국내 제품 층에 없는 것**: 식약처 의약품안전나라의 허가 상세·복약 정보(안전사용정보)·건강기능식품·식품안전지식, 약학정보원(health.kr) 의약품 정보, pharm.or.kr(의약품 식별표시·낱알식별 사이트) 정보. 의약품안전나라·식품안전나라는 자동 수집을 허용하지 않아(robots.txt) **공식 오픈API(공공데이터포털/식품안전나라 인증키)** 로만 받을 수 있고, health.kr·pharm.or.kr 은 데이터 이용 조건이 공개돼 있지 않아 제휴 확인이 필요합니다(pharm.or.kr 은 운영 기관이 페이지에 적혀 있지 않아 확정하지 못했고, 제목에는 ‘식품의약품안전처 & 약학정보원’이 보입니다). 식약처 허가정보용 수집 스크립트 `tools/fetch_mfds.mjs` 는 있으나 인증키가 필요해 사용자 PC에서 실행하는 것으로만 준비돼 있고 아직 돌려 보지 않았습니다.
- (v1.3.0) 한약제제 표시·묶음·증상어 대응은 **이름·ATC 규칙으로 추정한 수기 초안**입니다. "숙취해소 링거"가 정확히 무엇을 뜻하는지(허가 수액 제품 · 병원의 수액 조합 · 건강기능식품 중 무엇인지)는 약사 확인이 필요합니다.
- 두 심평원 파일의 `fetched`(받은 날)는 이 기록을 넣기 전에 받은 파일에 한해 파일 수정 시각으로 대신 적었습니다(`meta.fetch_note`).
