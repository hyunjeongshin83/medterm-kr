# MedTerm-KR 설계·검증 보고서 (프로토타입)

작성일 2026-10-28 · 범위: 「약무용어 전자사전·온톨로지·LLM 환각 제어」 계획서의 웹/앱 구현 착수본

## 1. 요약
- 계획서 5개 절 중 **(2) 데이터모델·계층구조**와 **(3) LLM 연계·환각 제어**를 동작하는 웹앱으로 구현했다. (1) 사례조사는 핵심 주장만 검증했고, (4) 데이터 확보와 (5) 실증은 이 프로토타입이 쓰이는 방법·지표만 정리했다.
- 사전 수록: 성분(VTM) 32 · 제형·용량(VMP) 516 · 제품(AMP) 410 (RxNorm 기준). 한글명·한국 상품명은 **수기 초안(약사 검수 전)** 이다.
- 검증기는 LLM 답변에서 약물명·ATC 코드·RxCUI·계열·단위용량을 사전과 대조해 `오류 / 확인 필요 / 정보 / 일치`로 표시한다. **사전에 없는 것은 "환각"이 아니라 "확인 필요"** 로 다룬다.
- 가장 중요한 한계: 사전에 없는 실존 약물명을 어간 규칙으로 찾는 재현율은 독립 평가에서 11/34 (32%, 95% CI 19–49%)였다. 전수 성분 목록(MFDS) 연동 없이는 이 약점이 해소되지 않는다.
- OWL/SKOS(Turtle) 내보내기는 완료했다(`data/medterm.ttl`, 트리플 7,640개). MFDS 연동은 이 환경에서 `apis.data.go.kr` 접근이 조직 허용 목록에 없어 직접 수행할 수 없고, 사용자 PC에서 수집 스크립트를 실행해 결과를 넘겨받는 방식으로 진행한다(§6).

## 3. 설계
### 3.1 계층·데이터모델 (OntoPharma식 상세도 수준)
```
VTM(성분)  1 ──< VMP(성분+함량+제형)  1 ──< AMP(제품/브랜드)
   │ hasATC ─▶ ATC 분류(SKOS broader: 5단계 → 1단계)
   └ 외부코드: RxCUI · ATC(여러 개 가능) · SNOMED CT ID
```
- VTM 필드: id, rxcui, 한글명·이명, 영문명·이명, 국내 상품명(수기), atc_codes[], atc_paths{code→경로}, snomed_ct[], review_status(draft/auto/reviewed), provenance.
- VMP: ingredient→VTM, strength{raw,value,unit,per}, form_en/form_ko, release_tech, pack_or_duration.
- AMP: vmp→VMP, brand_en, market("US (RxNorm SBD)"). **한국 허가 제품은 MFDS 연동으로 채울 자리**다.
- ATC가 성분당 여러 개인 것은 오류가 아니다(예: 이부프로펜 5개, 프레드니솔론 11개). 검증은 "어느 하나와 일치"로 판정한다.

### 3.2 환각 제어 파이프라인
1. **근거 검색**: 질문에서 약물 언급을 찾아 사전 항목을 추출 (`findMentions`, `search`).
2. **근거 주입 프롬프트**: 항목 JSON을 `<사전>`으로 주입하고 규칙 4개(사전 사실만 사용·없으면 "확인 불가"·개인 용량 판단 금지·단위용량은 미국 기준 명시)를 system에 둔다.
3. **LLM 호출**: 서버 프록시 URL만 입력(브라우저에 API 키를 두지 않음). 비워 두면 답변을 붙여넣어 검증.
4. **사후 검증**(결정론적 규칙, LLM 미사용):

| 검사 | 판정 | 비고 |
|---|---|---|
| 사전 약물명·상품명 일치 | 일치 | 상품명→성분 연결 |
| 사전 이름과 한두 글자 다른 철자·앞뒤 음절 부가 | 확인 필요 | 오타/변형 의심 |
| 약물명 어간(-프라졸, -스타틴 등)이 있으나 사전에 없음 | 확인 필요 | 실존 약물일 수 있음 |
| ATC 코드가 같은 문장의 약물 코드와 불일치 | **오류** | 다른 약물의 코드면 소유자를 안내 |
| RxCUI가 약물과 불일치 | **오류** | |
| 계열 용어("양성자펌프억제제" 등)가 약물 ATC와 불일치 | **오류**(약물 1개) / 확인 필요(여러 개) | 용어 사전은 수기 초안 |
| 약물 직후 "N mg"이 RxNorm(미국) 단위용량에 없음 | 확인 필요 | 적정 용량 판단 아님 |
| "하루/최대" 등 총량 맥락의 용량 | 정보 | 사전으로 검증 불가 |

### 3.3 화면 구성 (3단 반응형)
- 왼쪽: ATC 계통 트리 / 가나다순 목록과 트리 내 검색. 가운데: 작업 탭 5개(사전 검색·관계 그래프·답변 검증·근거 기반 질의·데이터·한계). 오른쪽: 선택한 성분의 상세(Inspector).
- 1100px 미만에서는 상세가 오른쪽 서랍으로, 700px 미만에서는 트리도 서랍(☰ 분류 탐색)으로 바뀐다. 순수 HTML·CSS·JS이며 외부 라이브러리·유료 도구를 쓰지 않는다.
- 관계 그래프 탭은 고른 성분 중심의 ego-network를 순수 SVG로 그린다(열: 같은 ATC 세부군 성분 · ATC 세부군 · ATC 코드 · 성분 · VMP · AMP). 표시 상한(ATC 6·같은 세부군 성분 6·VMP 10·AMP 14)을 넘으면 "외 N개" 노드로 알린다. **"같은 세부군 성분"은 사전에 수록된 32개 안에서만 찾으므로 실제 같은 계열 약물 전체가 아니다.**
- 성분을 고르면 주소에 `#MT:VTM:…`가 붙어 같은 항목을 공유할 수 있다(`file://`에서는 `history.replaceState`가 보안 오류를 내므로 `location.replace`를 사용).
- 사용자 디자인 파일(이미지·PDF)이 오면 색·글꼴·간격은 CSS 변수로, 배치는 이 구조를 기준으로 맞춘다.

## 4. 시험 결과
앱 정보 탭에도 같은 수치가 표시된다. **개발 세트는 사전에서 합성한 문장이라 단위 테스트이며 실제 LLM 답변의 성능이 아니다.**

| 세트 | 결과 | 의미 |
|---|---|---|
| 개발·정상 문장(ATC·용량·계열·RxCUI·일반 문장) | 148/148 오탐 없음 | 합성 |
| 개발·주입 오류(ATC·RxCUI·계열·용량·철자·가짜 이름) | 176/176 탐지 | 합성, 개발 중 수정 반영 |
| 개발·사전 밖 실존 약물 15개 | 15/15 표시 | 개발 중 어간 보강 후. '페니실린'은 약물명이면서 계열명이라 경고하지 않기로 하고 별도 1건(모호한 계열명, 1/1)으로 분리 |
| 보류 1 — 사전 밖 실존 약물 34개 (수정 **전**) | 27/34 (79%, 95% CI 63–90%) | 독립. 이후 이 세트로 결함 수정 → 더는 독립 아님 |
| 보류 2 — 사전 밖 실존 약물 34개 (수정 **후** 새로 평가) | 11/34 (32%, 95% CI 19–49%) | **독립. 현실적 재현율에 가장 가까운 수치** |

개발 중 벤치마크·샘플 점검으로 발견·수정한 결함: (a) "비스테로이드성 소염진통제" 안의 "스테로이드"가 다른 계열로 오인됨, (b) 이름 끝 "란"을 조사로 잘라 `다비가트란`을 놓침, (c) `데스로라타딘`이 안에 든 `로라타딘`만 보고 통과됨, (d) 사전에 없는 이름 `베르나스타틴` 안의 "스타틴"을 계열 용어로 읽어 거짓 오류를 냄. UI는 jsdom으로 130개 동작 점검(검색·검증·질의·XSS 입력·탭 전환, 3단 레이아웃의 트리·필터·가나다순·서랍 열기/닫기(Esc·닫기 버튼·바깥 클릭)·주소 해시 딥링크, 관계 그래프의 렌더링·상한 표기·노드 이동·키보드·확대/축소)을 통과했다. 그래프 모델·좌표는 DOM 없이 16개 항목으로 따로 점검했다(32개 성분 전부에서 ATC·같은 세부군 성분·VMP·AMP 개수가 Python이 원본 JSON에서 독립 계산한 값과 일치, 노드 겹침·범위 이탈·끝점 누락 없음). 화면 폭은 matchMedia를 흉내 낸 세 모드(넓음·태블릿·폰)로 나눠 점검했다. 단, **실제 브라우저의 시각적 렌더링(간격·겹침·글자 크기·미디어쿼리 적용, 그래프 글자가 노드 안에 들어가는지)은 확인하지 못했다**(그래프의 글자 폭은 글꼴을 측정한 값이 아니라 보수적 추정이다) — 헤드리스 브라우저가 이 환경에서 실행되지 않아 CSS는 문법·미정의 클래스·ID 참조만 정적 점검했다.

## 5. 한계
1. 사전은 성분 32개뿐이다. "사전에 없음"은 환각의 증거가 아니라 확인 필요 신호다.
2. 단위용량은 **미국 RxNorm에 있는 규격인가**만 본다. 국내 허가 규격·적정 용량·금기·상호작용은 다루지 않는다.
3. 한글명·상품명·계열 용어는 수기 초안이다(약사 검수·MFDS 대조 전).
4. 어간 규칙은 -프라졸/-스타틴 등 일부 계열 위주다. 보류 2에서 놓친 이름은 대부분 어간이 목록에 없는 계열(-콕시브, -맙, -타손 등)이었다.
5. "일치/오류 없음" 판정은 정확성 보증이 아니다. 사전에 있는 범위의 불일치가 없다는 뜻일 뿐이다.
6. 실제 LLM 호출은 연결하지 않았다(프록시 URL 입력 방식 + 모의 답변으로 시연). 호출 성능·비용은 미측정.

## 6. 다음 단계
1. **(완료) OWL/SKOS 내보내기**: `data/medterm.json` → `data/medterm.ttl`(`build/export_ontology.py`, 트리플 7,640개). rdflib로 다시 읽어 SPARQL로 확인함 — 클래스별 개체 수가 사전과 일치(VTM 32·VMP 516·AMP 410), A02BC 하위 성분 3개(오메프라졸·판토프라졸·에스오메프라졸), 성분 없는 VMP·VMP 없는 AMP·ATC 없는 VTM·성분 2개 이상인 VMP는 모두 0. **Protégé에서 열어 보는 것은 아직 하지 않았다**(rdflib 재로딩만 확인). 온톨로지 IRI는 자리표시용(`medterm-kr.example`)이므로 배포 시 교체한다.
2. **MFDS 연동**: 의약품 제품 허가 정보로 AMP(국내 제품)·한글 성분명 전수 적재 → 사전 밖 약물명 탐지의 근본 해법. 이 환경에서는 `apis.data.go.kr` 접근 요청이 거부되어(관리자 허용 목록) 사용자 PC에서 `tools/fetch_mfds.mjs`(서비스 DrugPrdtPrmsnInfoService08 — 포털의 현재 End Point. 07은 중지 예정 공지가 있었음 — 의 목록·주성분 상세 오퍼레이션)를 실행해 결과 파일을 넘겨받는다. 스크립트는 모의 서버로 17개 항목(페이징·이어받기·일일 한도 초과·키 비노출 등)을 통과했으나 **실제 MFDS 응답의 필드명은 미확인**이다 — 공개 명세가 불완전하여 첫 실행에서 출력되는 '첫 레코드 필드' 목록으로 확인한다.
3. **약사 검수 워크플로**: review_status를 draft→reviewed로 올리는 화면, 검수자·일시 기록.
4. **실증(계획서 5절)**: 가상 처방·약료 사례 N건에 대해 (1) 일반 LLM (2) 사전 근거 주입 (3) 근거 주입+사후 검증을 비교. 정답은 ATC/RxNorm·임상약학 지침으로 사전 정의, 약사 2인 독립 판독 후 Cohen's κ, 지표는 매핑 정확도·재현율·환각률. **실제 LLM 답변과 전문가 라벨 세트가 필요**하며 이 프로토타입의 합성 점검은 그 대체물이 아니다.
5. 용어 확장: 혼동 주의 쌍(LASA), DUR 규칙, FHIR(Medication/MedicationKnowledge) 매핑, 한글 제형명 확충.
6. 배포: 정적 호스팅 + 서버 프록시(키 보호, 호출 제한). 개인정보·의료기기 해당 여부 검토.

## 7. 실행·재현
- 열기: `web/index.html`을 더블클릭(서버 불필요).
- 사전 재생성: `python build/build_dictionary.py --out data/medterm.json` → `python build/make_bundle.py` (RxNav 호출, 약 1분).
- 벤치마크: `python tests/make_benchmark.py` (Node 필요, `NODE` 환경변수로 경로 지정). UI 점검: `tests/ui`에서 `npm install jsdom@24` 후 `node ui_test.js`.
- 온톨로지: `python build/export_ontology.py` (rdflib 필요) → `data/medterm.ttl`.
- MFDS 수집(사용자 PC): `.env`에 `DATA_GO_KR_KEY=인증키` 한 줄 저장 후 `node --env-file=.env tools/fetch_mfds.mjs --out <폴더>`; 점검: `node tools/test_fetch_mfds.mjs`.
- 데이터 출처: RxNorm/RxNav REST(NLM, 2026-10-28 수집), ATC 분류명은 RxClass 경유(WHO CC). ATC·SNOMED CT 사용 조건은 각 기관 라이선스를 따른다.

## 8. CLI와 파일럿 실험 (실제 LLM 답변)
### 8.1 CLI
`bin/medterm.mjs` — `info · search · show · prompt · verify · bench · eval` (사용법은 파일 머리말). `verify` 종료코드: 0=불일치·확인필요 없음, 2=확인 필요만, 1=사전 불일치(오류) 포함. `eval`은 답변 단위 JSONL(`condition, text, expert1[, expert2]`)을 받아 조건별 검증기 표시율과, 전문가 라벨이 있으면 민감도·특이도·PPV·Cohen's κ(검증기-전문가, 전문가 간)를 계산한다 — 계획서 5절 평가 지표용이다. `tests/test_cli.py` 24개 점검을 통과했고, `eval`의 지표는 손으로 계산한 기대값과 일치했다(예: 민감도 1/3, 특이도 2/3, κ=0).

### 8.2 파일럿 설계와 한계
- 범용 LLM 1종(모델명은 공개 저장소 문서에서 생략), 답변 104개: 사전 내 실존 약물 32개·가짜 이름 8개·사전 밖 실존 약물 12개 × 두 조건(A 일반 프롬프트 / B 사전 근거 주입). 같은 질문 "…의 ATC 코드, 약물 계열, 흔한 단위 용량(mg)".
- **정답 라벨이 없다.** 판정은 비전문가(본 에이전트)가 원문을 읽고 했고 판정자 LLM이 보조했다. 약사 판독이 아니다. 가짜 이름 8개는 '실존하지 않을 가능성이 높음'일 뿐 미검증이다.
- v1과 v2는 같은 질문이고, v2는 v1 결과를 보고 고친 뒤 다시 돌린 것이라 독립 평가가 아니다.

### 8.3 결과
| 질문 유형 (조건당 n) | 일반(A) | 근거 주입(B) | 해석 |
|---|---|---|---|
| 사전 내 실존 약물 (32) | 검증기 표시 0 | 검증기 표시 0, 사전 ID 인용 32/32 | 흔한 약이라 일반 조건도 오류가 없었다 → **근거 주입의 정확도 이점은 측정되지 않음(천장 효과)** |
| 가짜 이름 (8) | 환각·대체 답변 2/8 (95% CI 7–59%) | 0/8 (95% CI 0–32%) | 방향은 근거 주입에 유리하나 Fisher 정확검정 p=0.467로 **통계적으로 유의하지 않음**(표본 작음) |
| 사전 밖 실존 약물 (12) | 정보 제공 12/12 | "사전에 없음" 12/12(1건은 일반 지식을 덧붙임) | **근거 주입의 비용**: 사전이 32개 성분뿐이라 범위 밖 질문에는 도움이 되지 않는다 |

가짜 이름 일반 조건의 2건: 카도올롤을 카르테올롤로 바꿔 답하면서 알리지 않음(대체), 라도프라졸을 PPI로 소개하며 10·20mg 용량 제시(환각).

### 8.4 실제 답변에서 발견·수정한 검증기·프롬프트 결함
합성 벤치마크로는 찾지 못했고 실제 LLM 답변에서 나온 거짓 경보 3건과 프롬프트 결함 1건이다. 실존 약물 답변에서 표시된 3건은 모두 **검증기의 거짓 경보**였다(진짜 오류는 관찰되지 않음).
1. "비스테로이드성 소염제" 속 "스테로이드"를 코르티코스테로이드 계열 주장으로 읽음 → 수정.
2. "페니실린 계열" 등 계열명을 미등록 약물명으로 경고 → 계열명 허용 목록. 부작용: '페니실린'처럼 약물명이자 계열명인 용어는 경고하지 않는다.
3. 답변이 "복합제는 다른 ATC 코드(C09DA03…)"라고 쓴 문장을 단일 성분 코드 불일치로 처리 → 복합제 맥락 문장은 '정보(검증 불가)'로 낮춤. 부작용: 같은 문장에 "복합"이 들어가면 진짜 코드 오류도 오류로 올리지 않는다.
4. 검색 결과가 비면 모델이 "사전이 비어 있다"고 오해 → 프롬프트에 "전체 N개 성분 수록, 이 질문과는 관련 없음"을 명시.

남은 한계: 가짜 이름·사전 밖 약물은 답변이 거절이든 환각이든 **이름 언급 자체가 '확인 필요'로 표시**되어 검증기가 둘을 구분하지 못한다(8.3의 환각 판정은 검증기가 아니라 사람·LLM 판정이다).

### 8.5 예약 실행
이 환경에는 예약·반복 실행 기능이 없다(`host`의 기능 목록에서 확인). MFDS 수집의 일일 한도 이어받기용으로 사용자 PC에서 쓸 `tools/run_mfds_resume.cmd`를 제공한다(키 없이 로그·종료코드 기록만 시험했고 **작업 스케줄러 등록은 시험하지 못함**). 등록: `schtasks /Create /SC DAILY /ST 09:10 /TN MedTermMfdsFetch /TR "\"<프로젝트 경로>\tools\run_mfds_resume.cmd\"" /F`, 해제: `schtasks /Delete /TN MedTermMfdsFetch /F`.
