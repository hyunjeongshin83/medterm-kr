# 약사 검수 참여 안내 (검수 2·3단계 · v1.6.0)

> 약사 면허가 있는 분이 앱 안에서 직접 판정하고, 운영자(MedIT)가 면허를 따로 확인한 뒤 합치면 ‘검수 상태’의 2·3단계가 채워집니다. 앱이 스스로 ‘검수 완료’를 만들 길은 없습니다.
>
> **접수창(추가됨 · 아직 배포 전)**: 확인서를 내보내거나 보내기 전에 앱 화면에서 **동의서를 읽고 동의**해야 합니다. 운영자가 접수창을 열어 둔 판에서는 **‘MedIT로 보내기’** 로 운영자의 구글 시트(‘응답’ 탭)에 바로 쌓입니다. 운영자가 동의서 값(보유 기간·국외 이전 안내)을 채우기 전에는 앱이 확인서를 내보내지도 보내지도 못하게 막습니다. 자세한 것은 3절.

## 1. 한눈에

| 단계 | 누가 | 무엇을 | 끝났다는 기준 |
|---|---|---|---|
| 1 자료 대조 | 도구·운영자 | 공식 자료(심평원 약가마스터·위키데이터·법제처 본문)와 맞춰 봄 | 2026-11-06 했음 |
| 2 약사 확인 | 약사 | 항목마다 ‘맞다·다르다·모르겠다’ 표시 | 범위의 **모든 항목에** 현재 내용 기준 판정이 하나 이상 있음 |
| 3 약사 검수 완료 | 약사 + 운영자 | 판정을 ‘확인서’로 제출, 운영자가 면허 확인 후 합침 | 범위의 **모든 항목에** ‘확인서’의 ‘맞다’가 있고 ‘다르다’는 한 번도 없음 |

- 검수 범위는 둘입니다. **성분 한글명·국내 상품명 60개**(성분 32 + 상품 28)와 **약사법 쉬운 풀이 53개**(약무·제도 층이 있는 판에서만 나옵니다).
- 흐름: 약사가 앱에서 판정 → **동의서를 읽고 동의** → 확인서를 **파일로 저장·복사해 전달**하거나 **‘MedIT로 보내기’**(운영자가 접수창을 연 판에서만) → 운영자가 면허를 확인하고 병합 도구로 합침 → 다음 판의 ‘데이터·한계’ 탭 ‘검수 상태’에 반영.
- 합치기 전에는 ‘검수 상태’가 바뀌지 않습니다. 사전 검색·검증 기능은 서버로 아무것도 보내지 않습니다. 확인서는 약사님이 **동의한 뒤 ‘MedIT로 보내기’를 누를 때만** 운영자의 구글 시트로 갑니다(누르기 전에는 이 기기의 브라우저에만 있습니다). 안드로이드 앱은 인터넷 권한이 없어 보내기 단추가 없고 파일 전달만 됩니다.

## 2. 약사님께 — 참여하는 법

1. 앱의 **데이터·한계** 탭에서 ‘약사 검수 참여’ 카드의 **검수에 참여하기**를 누릅니다. 앱 주소 끝에 `#review` 를 붙이면(예: `…/app/#review`) 바로 이 카드가 열립니다.
2. **검수자 정보**: 이름(필수, 40자까지) · 소속(선택) · ‘약사 면허를 가지고 있습니다’ 표시. 이름·소속을 ‘검수 상태’에 공개해도 좋으면 공개 동의에 표시합니다. 표시하지 않으면 “비공개 약사 N명”으로만 나옵니다.
3. **검수 범위와 참고한 자료**: 범위(성분 한글명·상품명 / 약사법 쉬운 풀이)를 고르고, 판정에 참고한 자료(약학정보원 · 식약처 의약품안전나라 · 약학정보 책 · 법제처 약사법 본문 · 기타)에 표시합니다. 약학정보원과 약학정보 책은 약사님이 직접 열어 대조해 주세요. 화면의 내용을 복사해 오지 않습니다.
4. **항목마다 판정**: 각 항목을 읽고 셋 중 하나를 고릅니다.

| 판정 | 뜻 | 메모 |
|---|---|---|
| 맞다 | 사전에 적힌 말이 맞다 | 없음 |
| 다르다 | 사전에 적힌 말이 틀리거나 오해를 부른다 | “어떻게 다른가요?” 200자까지(선택) |
| 모르겠다 | 근거를 못 찾았거나 판단이 서지 않는다 | “무엇이 헷갈리시나요?” 200자까지(선택) |

   - **다음 안 한 항목으로** 단추가 아직 판정하지 않은 다음 항목으로 데려갑니다. **다르다·모르겠다만** 보기로 다시 확인할 항목만 모아 볼 수 있습니다.
   - 법령 항목(약사법)은 ‘법령 원문 발췌’를 펼쳐 풀이와 대조합니다. 시행 예정·개정 예정 표시가 붙은 항목은 예정판 원문도 함께 보입니다. 이 판정은 풀이의 쉬움과 정확함을 보는 것이며 법률 검토가 아닙니다.
   - 판정은 입력하는 즉시 **이 기기의 브라우저**에 저장됩니다. 창을 닫았다가 다시 열면 ‘이어서 판정하기’로 이어서 할 수 있습니다. 저장을 막는 환경에서는 이 창이 열려 있는 동안만 남으므로 중간에 ‘진행 상황 파일’을 내보내 두세요.
5. **동의서**: 내보내거나 보내기 전에 ‘개인정보 수집·이용 동의 (필수)’의 안내 8가지(수집하는 항목 · 수집·이용 목적 · 보유·이용 기간 · 받는 곳과 보관 장소 · 국외 이전 안내 · 동의하지 않을 권리와 불이익 · 이름·소속 공개 · 삭제 요청)를 읽고 칸에 표시합니다. 판정이 연구에도 쓰이는 데 동의하실 수 있으면 ‘연구 이용 동의 (선택)’도 표시합니다(운영자가 연구 정보를 채운 판에서만 나옵니다). **필수 동의에 표시하지 않으면 확인서를 내보내거나 보낼 수 없습니다.** 동의하지 않으셔도 사전을 쓰는 데에는 영향이 없습니다. 동의 표시는 저장하지 않으니 내보내거나 보낼 때마다 다시 표시합니다.
6. **확인서 내보내기·보내기**: ‘저는 약사로서 위 판정을 확인했으며, 이 판정이 ‘약사 검수’ 기록(3단계)에 쓰이는 것에 동의합니다.’ 칸(확인서 동의)에 표시하고 다음 중 하나를 누릅니다. 표시하지 않으면 ‘진행 상황 파일’이 되어 2단계에만 셉니다.
   - **MedIT로 보내기**(운영자가 접수창을 연 판에서만 보입니다): 확인서가 운영자의 구글 시트로 갑니다. “보냈습니다”가 나오면 받은 것입니다. “받았다는 답을 확인하지 못했습니다”가 나오면 운영자가 받았을 수도 못 받았을 수도 있으니, 다시 누르거나 파일로 저장해 전달해 주세요(같은 분의 같은 범위 제출은 합칠 때 하나로 봅니다). “동의서가 운영자가 받는 동의서와 달라…”가 나오면 앱을 새로 고쳐 최신 판으로 열고 동의서를 다시 읽고 동의해 주세요.
   - **파일로 저장(.json)** 또는 **복사하기**: 복사가 안 되는 환경(앱 안의 웹뷰 등)에서는 화면에 나타난 글 상자에서 직접 복사해 메시지나 메일에 붙여 넣으면 됩니다.
   - 이름·면허 표시·판정·동의가 빠져 있으면 무엇이 빠졌는지 알려 주고 확인서를 만들지 않습니다.
7. 파일(또는 글)로 낸 경우에는 이 앱을 알려 드린 **MedIT 담당자**에게 전달합니다. 범위마다 파일이 따로 나옵니다. ‘MedIT로 보내기’로 보낸 경우에는 따로 전달하지 않아도 됩니다.
8. 다른 기기에서 이어서 하려면 저장한 파일을 **저장해 둔 파일 불러오기**로 가져옵니다(파일 고르기 또는 글 붙여 넣기). 불러와도 면허 표시·확인서 동의·개인정보 동의는 가져오지 않으니 그 화면에서 직접 다시 표시해 주세요. **이 기기에서 모두 지우기**는 두 번 눌러야 지워집니다.

## 3. 운영자(MedIT)용

### 3-1. 접수창 준비 (처음 한 번 · 앱에서 바로 받으려면)

앱 화면의 동의서와 구글 시트(‘드라이브 엑셀’)로 받는 길입니다. 파일 전달만 쓸 거면 아래 표의 `retention`·`overseas` 두 칸만 채우면 됩니다.

1. **`web-react/review_intake.json` 에 값을 채웁니다**(한 번 채워 두면 다음 빌드부터 그대로 씁니다. 비밀번호·키는 넣지 않습니다).

| 칸 | 뜻 | 비어 있으면 |
|---|---|---|
| `retention` | 보유·이용 기간(예: 수집일부터 ○년, 목적 달성 시 파기) | 동의서가 ‘준비 안 됨’ → **앱이 확인서를 내보내지도 보내지도 못하게 막고** “동의서가 아직 준비되지 않아…” 안내 |
| `overseas` | 구글(국외) 보관 안내: 이전받는 자 · 나라 · 이전 일시·방법 · 항목 · 목적 · 보유 기간 · 거부 방법 | 위와 같음 |
| `research.responsible` · `research.retention` · `research.irb` | 연구책임자 · 연구 자료 보유·이용 기간 · IRB 승인번호와 승인일 | 세 칸이 모두 있어야 ‘연구 이용 동의(선택)’를 묻습니다. 비면 묻지 않고 ‘동의 안 함’으로 기록 |
| `endpoint` | 구글 앱스 스크립트 ‘웹 앱’ 배포 주소(`https://script.google.com/macros/s/…/exec`) | ‘MedIT로 보내기’ 단추가 없고 파일 전달만 됩니다 |

   - 동의서 글은 **초안이며 법률 자문이 아닙니다.** 개인정보 보호법의 안내 항목(제15조)·국외 이전(제28조의8)·연구 시 IRB 심의를 기준으로 썼습니다. 쓰기 전에 MedIT(또는 법률·IRB 담당)가 검토해 주세요. 연구책임자는 MedIT 대표이므로 이해관계(연구책임자가 사업 주체)도 동의서에 밝혀 둡니다.
   - 값이나 문구가 바뀌면 **동의서 판 번호**(`c-…`)가 자동으로 바뀝니다. 번호는 앱의 ‘동의서’ 단계에 보입니다.
   - 보내기 주소는 **독립 실행·설치형 웹앱** 빌드에만 들어갑니다. 안드로이드 앱(인터넷 권한 없음)·공유 페이지·나란히 보기에는 들어가지 않습니다.
2. **구글 시트 접수창을 만듭니다**(드라이브의 안내 문서 ‘MedTerm-KR 약사 확인서 접수창 만들기’ 최신 판을 따라 하세요). 새 구글 시트 → 확장 프로그램 → Apps Script 에 `tools/google_apps_script/review_inbox.gs` 를 통째로 붙여 넣기 → 시트 메뉴 ‘처음 설정’ → ‘웹 앱’으로 배포(실행: 나 · 액세스: 모든 사용자) → 나온 `/exec` 주소를 `endpoint` 에 넣고 다시 빌드 → 시트 메뉴 **‘앱 접수 열기’** 에 앱에 보이는 동의서 판 번호를 넣습니다(닫으려면 ‘앱 접수 닫기’). 열기 전에는 서버가 모두 거절합니다(코드 `closed`).
   - **한 시트에는 구글 폼과 앱 접수 중 한 가지 경로만** 연결합니다.
3. **시트의 ‘응답’ 탭**: 타임스탬프 · 확인서(JSON) · 개인정보 수집·이용 동의(1단계·필수) · 연구 이용 동의(2단계·선택) · 면허확인(운영자 기입) · 접수 경로(앱 / 앱(시험)) · 동의서 버전 · 앱 버전. 시트는 엑셀(.xlsx)로 내려받을 수 있습니다. **면허를 확인한 줄에만 ‘면허확인’ 칸에 Y 를 적으세요.** 연구용 분석(‘접수 점검’ · 가명 번호 분석 · 주간 요약 메일)에는 ‘연구 이용 동의’와 ‘면허확인 Y’가 둘 다 있는 줄만 들어갑니다. 이름·소속·메모는 분석에 넣지 않습니다(운영자 탭에만 있음).
4. **보내기 주소는 공개 주소입니다**(“모든 사용자”). 누구나 글을 보낼 수 있으므로 서버가 형식 · 항목 내용 표시(해시) · 동의서 판 · 동의 표시 · 크기 · 행 수(기본 3000) · 초안 여부를 검사해 거르고, 면허를 따로 확인하기 전에는 합치지 않는 것이 마지막 방어선입니다. 낯선 줄이 생기면 ‘앱 접수 닫기’로 닫고 줄을 지웁니다.

### 3-1b. 연구자 페이지 — 요약 메일을 받을 주소를 연구자가 직접 등록 (선택 · 스크립트 1.2)

운영자가 지정한 연구자(예: 연구 책임 교수님)가 **메일로 본인 확인을 한 뒤** 주간 요약 메일을 받을 주소를 직접 넣고 뺄 수 있는 화면입니다. 접수창 웹 앱 주소 끝에 `?page=researcher` 를 붙여 엽니다(`https://script.google.com/macros/s/…/exec?page=researcher`). 이 화면에는 확인서·분석·약사의 이름·소속·메모가 **나오지 않습니다**(받는 주소 관리만 합니다).

**운영자가 할 일**

1. 최신 `review_inbox.gs`(스크립트 판 1.2)를 붙여 넣고 **웹 앱을 새 버전으로 다시 배포**합니다(배포 관리 → 편집 → 새 버전). `/exec` 주소는 그대로입니다.
2. 시트 메뉴 **MedTerm-KR → 연구자 페이지 → 연구자 지정**에 연구자 메일 주소를 한 개 적습니다(최대 3명). 취소는 ‘연구자 지정 취소’입니다 — 그 연구자가 등록한 받는 주소도 함께 지워지고, 열려 있던 화면도 바로 쓸 수 없게 됩니다.
3. 같은 하위 메뉴의 **‘연구자 페이지 현황·주소’** 에서 연구자 페이지 주소 · 지정된 연구자 · 등록된 주소 · 최근 기록을 봅니다. 주소가 `/dev` 로 끝나면 시험용이라 연구자가 열 수 없습니다. 배포 관리의 `/exec` 주소를 쓰세요. 그 주소를 연구자에게 알려 주세요.
4. (선택) 스크립트 속성 `RECIPIENT_DOMAINS`(쉼표로 구분한 도메인, 예: `sookmyung.ac.kr`)를 넣으면 그 도메인의 주소만 등록할 수 있습니다.
5. 잘못 등록된 주소는 메뉴 **‘받는 주소 지우기(운영자)’** 로 지웁니다. 운영자 주소(`SUMMARY_TO`)는 ‘처음 설정’에서만 바꾸며 연구자가 지울 수 없습니다. 연구자 메일 주소는 코드에 적지 않고 이 메뉴로만 넣습니다.

**연구자가 하는 일**

1. 주소를 열고 연구자 메일 주소를 적어 **인증 번호**를 받습니다(6자리 · 10분 유효 · 5번까지 틀릴 수 있음 · 한 번 쓰면 끝). 지정되지 않은 주소에는 메일이 가지 않지만 화면 안내는 똑같습니다.
2. 번호를 넣으면 로그인됩니다. 쓰지 않고 30분이 지나면(또는 처음부터 2시간이 지나면) 다시 인증해야 합니다.
3. **본인 주소**는 바로 추가됩니다. **다른 주소**(예: 연구실 공용 메일)는 추가를 누르면 **그 주소로** 인증 번호가 가고, 그 번호를 입력해야 추가됩니다. 운영자 주소를 빼고 5개까지 등록할 수 있고, ‘지우기’로 뺍니다.
4. 이후 매주 월요일 아침(9시쯤) 요약 메일이 운영자 주소와 등록된 주소마다 **한 통씩 따로** 갑니다(받는 사람끼리 주소가 보이지 않고, 등록된 주소 쪽 메일 끝에 “연구자 페이지에서 등록된 주소로 보냈습니다” 한 줄이 붙습니다). 운영자 주소로 먼저 보내고, 등록된 주소 중 일부가 실패해도(메일 한도 등) 나머지는 보냅니다.

**남용 방지 한도**: 같은 주소의 로그인 번호 요청 1시간 3번 · 연구자 1명의 ‘다른 주소’ 인증 메일 1시간 3통 · 인증 메일 하루 20통 · 이 스크립트가 보내는 모든 메일 하루 60통(구글 일반 계정의 메일 한도는 하루 약 100통). 한도에 닿으면 화면은 같은 안내를 하되 메일은 가지 않습니다. 시험 단계의 요약 메일 제목에는 `[시험용·가짜 데이터]` 표시가 붙습니다.

### 3-2. 받은 확인서를 합치는 법

0. 시트로 받은 경우 ‘확인서(JSON)’ 칸의 글을 `.json` 파일로 저장해 아래 도구에 넣습니다(파일로 받은 것과 같은 형식입니다).
1. **면허를 먼저 확인합니다.** 앱과 도구는 면허를 확인하지 못합니다. 확인서의 ‘면허 표시’는 약사가 스스로 한 표시일 뿐이므로, 합치기 전에 운영자가 약사 본인과 면허를 **따로** 확인합니다. 확인하지 않았으면 합치지 않습니다(도구도 `--license-verified` 없이는 거부합니다). 면허번호는 받지도 적지도 않습니다.
2. 파일을 검토합니다(저장하지 않음).

```
python -I tools/merge_pharmacist_reviews.py 받은파일.json --license-verified --dry-run
```

   형식·범위 해시·항목 번호·판정값·동의 기록(`consent`)을 검증하고, 합친 뒤의 현황과 동의 기록(동의서 판 · 연구 이용 동의 여부)을 미리 보여 줍니다. 규칙에 어긋난 파일(개인정보 수집·이용 동의가 `true` 가 아닌 것 포함)은 이유와 함께 거부합니다(종료 코드 2). 동의 기록이 없는 옛 파일은 경고만 붙여 받으니, 경고가 나오면 동의를 받은 근거를 따로 확인하세요.
3. 합칩니다. 공개에 동의한 약사는 이름·소속이 같으면 같은 검수자(P1, P2…)로 보고, 비공개 약사가 다시 낸 파일은 `--reviewer-id P1` 처럼 번호를 지정해야 같은 검수자로 합칩니다. 같은 검수자·같은 범위의 새 제출은 항목별로 이전 판정을 덮어씁니다(진행 상황 파일이 이전 확인서의 ‘맞다’를 덮으면 그 항목은 확인서 기준에서 빠집니다).

```
python -I tools/merge_pharmacist_reviews.py 받은파일.json --license-verified --verified-on 2026-11-20 --report 검수보고_P1.md
```

   - 결과는 `data/review/pharmacist_reviews.json` 에 쌓입니다. 이름·소속은 검수자가 공개에 동의한 경우에만 저장하고, 동의하지 않은 검수자는 번호(P1…)만 남습니다.
   - `--report` 보고서에는 ‘다르다·모르겠다’의 **메모**가 들어 있습니다. 메모는 저장 자료에 넣지 않으므로 이 보고서가 유일한 기록입니다. 보고서는 운영자만 보고 저장소에는 올리지 않습니다.
4. 저장 자료를 점검하고 현황을 봅니다.

```
python -I tools/merge_pharmacist_reviews.py --check
python -I tools/merge_pharmacist_reviews.py --status
```

5. 앱에 반영합니다. 병합 결과는 빌드 때 계산되어 앱에 담깁니다(앱이 현황을 직접 계산하지 않습니다).

```
python3 build/make_bundle.py
cd web-react && npm run build && npm test
```

6. ‘다르다’가 나온 항목은 사전을 고칩니다. 고치면 그 항목의 내용 표시(해시)가 바뀌어, 이전 판정은 자동으로 ‘다시 확인 필요’로 빠지고 세지 않습니다. 고친 항목을 약사에게 다시 확인받으면 3단계로 갑니다.

## 4. ‘검수 상태’가 계산되는 규칙

- 앱에 담긴 현황은 `build/review_lib.py` 가 한 곳에서 계산합니다. 화면(JavaScript)은 그 값을 보여 주기만 합니다.
- **내용 표시(해시)**: 항목마다 내용에서 만든 표시가 있고, 판정은 그 표시가 지금 내용과 같을 때만 셉니다. 사전 내용이 바뀐 항목의 지난 판정은 ‘다시 확인 필요’입니다. 범위 전체의 해시도 확인서에 들어 있어 낡은 확인서를 알아봅니다.
- **면허 확인일**이 없는 기록은 세지 않습니다(병합 도구는 `--license-verified` 로만 확인일을 남깁니다).
- 한 항목에 여러 약사의 판정이 있으면: 한 명이라도 ‘다르다’이면 ‘고칠 항목’, 아니면 ‘맞다’가 하나라도 있을 때 ‘확인됨’, 둘 다 없으면 ‘모르겠다만’입니다.
- 2단계 = 모든 항목에 판정이 하나 이상. 3단계 = 모든 항목이 ‘확인서의 맞다’로 확인됨(‘다르다’ 없음).
- 이 화면에 없는 범위(약무·제도 층이 없는 판의 약사법 범위)는 세지 않습니다.
- 제목의 기준일은 마지막 면허 확인일입니다.

## 5. 개인정보·보관 원칙

- 입력은 이 기기의 브라우저(localStorage 키 `medterm-kr-review-v1`)에만 저장되고(자동 저장은 서버로 보내지 않습니다), ‘이 기기에서 모두 지우기’로 지울 수 있습니다.
- **서버로 가는 것은 약사님이 동의한 뒤 ‘MedIT로 보내기’를 누를 때의 확인서 한 건뿐입니다**(그 단추가 있는 판에서만). 가는 곳은 운영자의 구글 시트이고, 쿠키·참조 주소(Referer)는 보내지 않습니다. 파일·복사로 전달하는 길에서는 약사님이 직접 전달할 때만 운영자에게 갑니다. 안드로이드 앱은 인터넷 권한이 없어 어느 경우에도 스스로 보내지 못합니다.
- **면허번호와 연락처는 받지 않습니다.** 확인서에는 이름·소속·면허 표시·참고 자료·판정·메모와 동의 기록(동의서 판 · 필수 동의 · 연구 이용 동의 여부 · 날짜)만 들어 있습니다.
- 이름·소속은 공개에 동의한 경우에만 저장하고 ‘검수 상태’에 나옵니다. 동의하지 않으면 “비공개 약사 N명”으로만 셉니다.
- ‘다르다·모르겠다’의 **메모는 저장소에 보관하지 않습니다.** 운영자 보고서(와 시트의 운영자 전용 탭)에만 있습니다.
- 확인서 동의(‘제 판정이 맞습니다’)와 개인정보 수집·이용 동의는 기기에 저장하지 않고 내보내거나 보낼 때마다 다시 표시합니다.
- 구글 시트는 구글 서버(미국 등)에 보관될 수 있습니다. 이 점은 동의서의 ‘국외 이전 안내’에 운영자가 적은 대로 알립니다. 약사님이 삭제를 요청하면 운영자가 시트의 해당 줄을 지웁니다(운영자가 합쳐 저장소에 반영한 판정은 번호(P1…)만 남는 기록이라 별도로 정리합니다).
- 연구자 페이지를 쓰면 스크립트 속성(운영자 전용)에 **연구자 메일 주소 · 요약 메일 받는 주소 · 등록한 연구자와 시각 · 최근 기록 40줄**이 남습니다. 인증 번호(소금을 섞은 해시)와 로그인 표(토큰의 해시가 열쇠)는 구글 캐시에 짧게만 두고 속성에는 저장하지 않으며, 화면은 토큰을 브라우저 저장소·쿠키에 남기지 않습니다. 약사의 개인정보와는 따로 있고, 연구자 메일 주소는 저장소에 올리지 않습니다(코드에 적지 않음).
- 시트의 확인서(JSON)에는 이름·소속이 들어 있고 **저장소는 공개일 수 있습니다.** 시트·받은 파일·병합 결과·보고서는 저장소에 올리지 않습니다(병합 도구의 저장 자료에는 공개 동의한 이름만 남습니다).

## 6. 확인서 형식 (`medterm-kr-review/1`)

```json
{
  "schema": "medterm-kr-review/1",
  "scope": "names",
  "scope_hash": "a42f57e6f1b0",
  "app": "1.6.0",
  "created": "2026-11-20",
  "reviewer": { "name": "홍길동", "affiliation": "새봄약국", "public": false, "license_claimed": true },
  "refs": ["health.kr", "book"],
  "refs_other": "",
  "attested": true,
  "consent": { "version": "c-0123456789", "collect": true, "research": false, "date": "2026-11-20" },
  "answers": {
    "N-161": { "v": "ok", "h": "0579f93d78" },
    "B-161-d2cc30": { "v": "diff", "h": "7c902f986b", "m": "메모(다르다·모르겠다만, 200자까지)" }
  }
}
```

| 칸 | 값 |
|---|---|
| `scope` | `names`(성분 한글명·국내 상품명) · `law`(약사법 쉬운 풀이) |
| `scope_hash` | 범위의 현재 내용 표시. 사전 내용이 바뀌면 달라집니다 |
| `refs` | `health.kr` · `mfds` · `book` · `law` · `other`(`refs_other` 에 이름) |
| `attested` | `true` 면 확인서, `false` 면 진행 상황 파일(2단계에만 셈) |
| `consent` | 동의 기록(앱의 동의서가 준비된 판에서만 들어감): `version`(동의서 판 · 영문·숫자·`.`·`_`·`-` 40자까지) · `collect`(필수 동의 · 반드시 `true`) · `research`(연구 이용 선택 동의 · `true`/`false`) · `date`(동의한 날). 구글 시트 서버가 받을 때 검사하고, 병합 도구가 한 번 더 봅니다. `collect` 가 `true` 가 아니거나 `draft` 가 `true`(동의서가 확정되기 전에 만든 확인서)이거나 모양이 틀리면 합치지 않습니다(종료 코드 2). 칸이 아예 없는 옛 파일(동의서가 생기기 전 판)은 합치되 “동의 기록 없음” 경고를 출력하므로, 그때는 약사에게 동의를 받은 근거를 따로 확인하세요. 동의 기록은 병합 보고서에는 남지만 저장 자료에는 넣지 않습니다(시트와 받은 파일에만 있음) |
| `answers` | 항목 번호 → `v`(`ok` · `diff` · `unsure`) · `h`(항목 내용 표시) · `m`(메모, `diff`·`unsure` 에만) |
| 항목 번호 | `N-<성분코드>`(성분 한글명) · `B-<성분코드>-<해시>`(국내 상품명) · `L-<조문>`(약사법) |

병합 도구는 이 형식만 받습니다. 이 자료에 없는 항목 번호·알 수 없는 판정값·길이 한도(이름 40 · 소속 80 · 메모 300 · 기타 80자) 초과·제어 문자·보이지 않는 글자·1MB 넘는 파일·`consent` 규칙 위반(위 표)은 파일 전체를 거부합니다. 항목 내용 표시(`h`)가 지금 사전과 다른 판정은 경고와 함께 반영하지 않습니다(앱 판이 다르거나 사전이 바뀐 경우).

## 7. 한계

- ‘MedIT로 보내기’로 보내도 ‘검수 상태’는 바로 바뀌지 않습니다. 운영자가 면허를 확인해 합치고 다시 빌드해 배포해야 바뀝니다. 보내기 주소와 동의서 값(보유 기간·국외 이전 안내)이 비어 있는 판에서는 단추가 없거나 확인서 내보내기 자체가 막힙니다.
- 면허 확인은 사람이 합니다. 이 도구는 확인서가 형식에 맞는지와 운영자가 확인했다고 표시했는지만 봅니다.
- **실제 구글 앱스 스크립트 웹 앱에서의 동작(주소 이동 · 답을 읽을 수 있는지 · 권한 화면 · 사용량 한도)은 이 저장소의 시험으로 확인하지 못했습니다.** 시험은 진짜 서버 코드(`review_inbox.gs`)를 가짜 구글 장치에 올리고, 앱의 요청을 가짜 주소에서 가로채 답하는 방식입니다. 배포한 뒤 ‘앱 접수 열기’ → 앱에서 가짜 판정으로 시험 글을 한 번 보내 시트에 줄이 생기는지 직접 확인해 주세요. 답을 읽지 못하면 앱은 “받았다는 답을 확인하지 못했습니다”라고 알립니다(보냈다고 하지 않습니다).
- 보내기 주소가 공개이므로 가짜·장난 글이 올 수 있습니다. 걸러 주는 것은 형식·내용 표시·동의서 판 검사와 행 수 한도, 그리고 면허 확인 전에는 합치지 않는 절차입니다.
- 동의서 글은 초안이며 법률 자문이 아닙니다. 연구에 쓰려면 IRB 심의와 동의서 문구 검토가 먼저입니다(`research` 세 칸을 채우기 전에는 연구 이용 동의를 묻지 않습니다).
