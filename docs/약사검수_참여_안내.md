# 약사 검수 참여 안내 (검수 2·3단계 · v1.6.0)

> 약사 면허가 있는 분이 앱 안에서 직접 판정하고, 운영자(MedIT)가 면허를 따로 확인한 뒤 합치면 ‘검수 상태’의 2·3단계가 채워집니다. 앱이 스스로 ‘검수 완료’를 만들 길은 없습니다.

## 1. 한눈에

| 단계 | 누가 | 무엇을 | 끝났다는 기준 |
|---|---|---|---|
| 1 자료 대조 | 도구·운영자 | 공식 자료(심평원 약가마스터·위키데이터·법제처 본문)와 맞춰 봄 | 2026-11-06 했음 |
| 2 약사 확인 | 약사 | 항목마다 ‘맞다·다르다·모르겠다’ 표시 | 범위의 **모든 항목에** 현재 내용 기준 판정이 하나 이상 있음 |
| 3 약사 검수 완료 | 약사 + 운영자 | 판정을 ‘확인서’로 제출, 운영자가 면허 확인 후 합침 | 범위의 **모든 항목에** ‘확인서’의 ‘맞다’가 있고 ‘다르다’는 한 번도 없음 |

- 검수 범위는 둘입니다. **성분 한글명·국내 상품명 60개**(성분 32 + 상품 28)와 **약사법 쉬운 풀이 53개**(약무·제도 층이 있는 판에서만 나옵니다).
- 흐름: 약사가 앱에서 판정 → 확인서 파일을 저장하거나 복사 → 이 앱을 알려 드린 MedIT 담당자에게 전달 → 운영자가 면허를 확인하고 병합 도구로 합침 → 다음 판의 ‘데이터·한계’ 탭 ‘검수 상태’에 반영.
- 합치기 전에는 ‘검수 상태’가 바뀌지 않습니다. 앱에는 서버가 없고 네트워크 요청도 하지 않아, 제출은 약사가 파일(또는 글)을 직접 전달하는 방식입니다.

## 2. 약사님께 — 참여하는 법

1. 앱의 **데이터·한계** 탭에서 ‘약사 검수 참여’ 카드의 **검수에 참여하기**를 누릅니다. 앱 주소 끝에 `#review` 를 붙이면(예: `…/app/#review`) 바로 이 카드가 열립니다.
2. **검수자 정보**: 이름(필수, 40자까지) · 소속(선택) · ‘약사 면허를 가지고 있습니다’ 표시. 이름·소속을 ‘검수 상태’에 공개해도 좋으면 공개 동의에 표시합니다. 표시하지 않으면 “비공개 약사 N명”으로만 나옵니다.
3. **검수 범위와 참고한 자료**: 범위(성분 한글명·상품명 / 약사법 쉬운 풀이)를 고르고, 판정에 참고한 자료(약학정보원 · 식약처 의약품안전나라 · 약학정보 책 · 법제처 약사법 본문 · 기타)에 표시합니다. 약학정보원과 약학정보 책은 약사님이 직접 열어 대조해 주세요. 화면의 내용을 복사해 오지 않습니다.
4. **항목마다 판정**: 각 항목을 읽고 셋 중 하나를 고릅니다.

| 판정 | 뜻 | 메모 |
|---|---|---|
| 맞다 | 사전에 적힌 말이 맞다 | 없음 |
| 다르다 | 사전에 적힌 말이 틀리거나 오해를 부른다 | “어떻게 다른가요?” 200자까지(선택) |
| 모르겠다 | 근거를 못 찾았거나 판단이 서지 않는다 | “무엇이 헷갈리시나요?” 200자까지(선택) |

   - **다음 안 한 항목으로** 단추가 아직 판정하지 않은 다음 항목으로 데려갑니다. **다르다·모르겠다만** 보기로 다시 확인할 항목만 모아 볼 수 있습니다.
   - 법령 항목(약사법)은 ‘법령 원문 발췌’를 펼쳐 풀이와 대조합니다. 시행 예정·개정 예정 표시가 붙은 항목은 예정판 원문도 함께 보입니다. 이 판정은 풀이의 쉬움과 정확함을 보는 것이며 법률 검토가 아닙니다.
   - 판정은 입력하는 즉시 **이 기기의 브라우저**에 저장됩니다. 창을 닫았다가 다시 열면 ‘이어서 판정하기’로 이어서 할 수 있습니다. 저장을 막는 환경에서는 이 창이 열려 있는 동안만 남으므로 중간에 ‘진행 상황 파일’을 내보내 두세요.
5. **확인서 내보내기**: ‘저는 약사로서 위 판정을 확인했으며, 이 판정이 ‘약사 검수’ 기록(3단계)에 쓰이는 것에 동의합니다.’ 칸(확인서 동의)에 표시하고 **파일로 저장(.json)** 또는 **복사하기**를 누릅니다. 표시하지 않으면 ‘진행 상황 파일’이 되어 2단계에만 셉니다. 복사가 안 되는 환경(앱 안의 웹뷰 등)에서는 화면에 나타난 글 상자에서 직접 복사해 메시지나 메일에 붙여 넣으면 됩니다. 이름·면허 표시·판정이 빠져 있으면 무엇이 빠졌는지 알려 주고 확인서를 만들지 않습니다.
6. 파일(또는 글)을 이 앱을 알려 드린 **MedIT 담당자**에게 전달합니다. 범위마다 파일이 따로 나옵니다.
7. 다른 기기에서 이어서 하려면 저장한 파일을 **저장해 둔 파일 불러오기**로 가져옵니다(파일 고르기 또는 글 붙여 넣기). 불러와도 면허 표시와 확인서 동의는 가져오지 않으니 그 화면에서 직접 다시 표시해 주세요. **이 기기에서 모두 지우기**는 두 번 눌러야 지워집니다.

## 3. 운영자(MedIT)용 — 받은 확인서를 합치는 법

1. **면허를 먼저 확인합니다.** 앱과 도구는 면허를 확인하지 못합니다. 확인서의 ‘면허 표시’는 약사가 스스로 한 표시일 뿐이므로, 합치기 전에 운영자가 약사 본인과 면허를 **따로** 확인합니다. 확인하지 않았으면 합치지 않습니다(도구도 `--license-verified` 없이는 거부합니다). 면허번호는 받지도 적지도 않습니다.
2. 파일을 검토합니다(저장하지 않음).

```
python -I tools/merge_pharmacist_reviews.py 받은파일.json --license-verified --dry-run
```

   형식·범위 해시·항목 번호·판정값을 검증하고, 합친 뒤의 현황을 미리 보여 줍니다. 규칙에 어긋난 파일은 이유와 함께 거부합니다(종료 코드 2).
3. 합칩니다. 공개에 동의한 약사는 이름·소속이 같으면 같은 검수자(P1, P2…)로 보고, 비공개 약사가 다시 낸 파일은 `--reviewer-id P1` 처럼 번호를 지정해야 같은 검수자로 합칩니다. 같은 검수자·같은 범위의 새 제출은 항목별로 이전 판정을 덮어씁니다(진행 상황 파일이 이전 확인서의 ‘맞다’를 덮으면 그 항목은 확인서 기준에서 빠집니다).

```
python -I tools/merge_pharmacist_reviews.py 받은파일.json --license-verified --verified-on 2026-11-20 --report 검수보고_P1.md
```

   - 결과는 `data/review/pharmacist_reviews.json` 에 쌓입니다. 이름·소속은 검수자가 공개에 동의한 경우에만 저장하고, 동의하지 않은 검수자는 번호(P1…)만 남습니다.
   - `--report` 보고서에는 ‘다르다·모르겠다’의 **메모**가 들어 있습니다. 메모는 저장 자료에 넣지 않으므로 이 보고서가 유일한 기록입니다. 보고서는 운영자만 보고 저장소에는 올리지 않습니다.
4. 저장 자료를 점검하고 현황을 봅니다.

```
python -I tools/merge_pharmacist_reviews.py --check
python -I tools/merge_pharmacist_reviews.py --status
```

5. 앱에 반영합니다. 병합 결과는 빌드 때 계산되어 앱에 담깁니다(앱이 현황을 직접 계산하지 않습니다).

```
python3 build/make_bundle.py
cd web-react && npm run build && npm test
```

6. ‘다르다’가 나온 항목은 사전을 고칩니다. 고치면 그 항목의 내용 표시(해시)가 바뀌어, 이전 판정은 자동으로 ‘다시 확인 필요’로 빠지고 세지 않습니다. 고친 항목을 약사에게 다시 확인받으면 3단계로 갑니다.

## 4. ‘검수 상태’가 계산되는 규칙

- 앱에 담긴 현황은 `build/review_lib.py` 가 한 곳에서 계산합니다. 화면(JavaScript)은 그 값을 보여 주기만 합니다.
- **내용 표시(해시)**: 항목마다 내용에서 만든 표시가 있고, 판정은 그 표시가 지금 내용과 같을 때만 셉니다. 사전 내용이 바뀐 항목의 지난 판정은 ‘다시 확인 필요’입니다. 범위 전체의 해시도 확인서에 들어 있어 낡은 확인서를 알아봅니다.
- **면허 확인일**이 없는 기록은 세지 않습니다(병합 도구는 `--license-verified` 로만 확인일을 남깁니다).
- 한 항목에 여러 약사의 판정이 있으면: 한 명이라도 ‘다르다’이면 ‘고칠 항목’, 아니면 ‘맞다’가 하나라도 있을 때 ‘확인됨’, 둘 다 없으면 ‘모르겠다만’입니다.
- 2단계 = 모든 항목에 판정이 하나 이상. 3단계 = 모든 항목이 ‘확인서의 맞다’로 확인됨(‘다르다’ 없음).
- 이 화면에 없는 범위(약무·제도 층이 없는 판의 약사법 범위)는 세지 않습니다.
- 제목의 기준일은 마지막 면허 확인일입니다.

## 5. 개인정보·보관 원칙

- 서버로 보내는 것이 없습니다. 입력은 이 기기의 브라우저(localStorage 키 `medterm-kr-review-v1`)에만 저장되고, ‘이 기기에서 모두 지우기’로 지울 수 있습니다.
- **면허번호와 연락처는 받지 않습니다.** 확인서에는 이름·소속·면허 표시·참고 자료·판정·메모만 들어 있습니다.
- 이름·소속은 공개에 동의한 경우에만 저장하고 ‘검수 상태’에 나옵니다. 동의하지 않으면 “비공개 약사 N명”으로만 셉니다.
- ‘다르다·모르겠다’의 **메모는 저장소에 보관하지 않습니다.** 운영자 보고서에만 있습니다.
- 확인서 동의(‘제 판정이 맞습니다’)는 기기에 저장하지 않고 내보낼 때마다 다시 표시합니다.

## 6. 확인서 형식 (`medterm-kr-review/1`)

```json
{
  "schema": "medterm-kr-review/1",
  "scope": "names",
  "scope_hash": "a42f57e6f1b0",
  "app": "1.6.0",
  "created": "2026-11-20",
  "reviewer": { "name": "홍길동", "affiliation": "새봄약국", "public": false, "license_claimed": true },
  "refs": ["health.kr", "book"],
  "refs_other": "",
  "attested": true,
  "answers": {
    "N-161": { "v": "ok", "h": "0579f93d78" },
    "B-161-d2cc30": { "v": "diff", "h": "7c902f986b", "m": "메모(다르다·모르겠다만, 200자까지)" }
  }
}
```

| 칸 | 값 |
|---|---|
| `scope` | `names`(성분 한글명·국내 상품명) · `law`(약사법 쉬운 풀이) |
| `scope_hash` | 범위의 현재 내용 표시. 사전 내용이 바뀌면 달라집니다 |
| `refs` | `health.kr` · `mfds` · `book` · `law` · `other`(`refs_other` 에 이름) |
| `attested` | `true` 면 확인서, `false` 면 진행 상황 파일(2단계에만 셈) |
| `answers` | 항목 번호 → `v`(`ok` · `diff` · `unsure`) · `h`(항목 내용 표시) · `m`(메모, `diff`·`unsure` 에만) |
| 항목 번호 | `N-<성분코드>`(성분 한글명) · `B-<성분코드>-<해시>`(국내 상품명) · `L-<조문>`(약사법) |

병합 도구는 이 형식만 받습니다. 이 자료에 없는 항목 번호·알 수 없는 판정값·길이 한도(이름 40 · 소속 80 · 메모 300 · 기타 80자) 초과·제어 문자·보이지 않는 글자·1MB 넘는 파일은 파일 전체를 거부합니다. 항목 내용 표시(`h`)가 지금 사전과 다른 판정은 경고와 함께 반영하지 않습니다(앱 판이 다르거나 사전이 바뀐 경우).

## 7. 한계

- 서버가 없어 제출은 파일 전달입니다. 앱에서 바로 ‘제출’되지 않으며, 운영자가 합치고 다시 빌드해 배포해야 ‘검수 상태’가 바뀝니다.
- 면허 확인은 사람이 합니다. 이 도구는 확인서가 형식에 맞는지와 운영자가 확인했다고 표시했는지만 봅니다.
- 안드로이드 앱(웹뷰)에서는 파일 저장·복사가 막힐 수 있습니다. 그럴 때는 글 상자에서 직접 복사하고, 불러올 때는 ‘글 붙여 넣기’를 씁니다.
- 지금 배포본은 아직 아무도 판정하지 않은 상태(모든 항목 ‘약사 검수 전 초안’)입니다. 실제 약사 판정이 합쳐지기 전에는 ‘검수 상태’가 예전 문구 그대로입니다.
- 이 판정은 사전 표기·풀이의 확인이며 임상 판단·법률 검토가 아닙니다.
