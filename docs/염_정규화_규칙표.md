# 염·수화물·약어 정규화 규칙표 (자동 생성)

> 이 문서는 `tools/norm_rules_table.py` 가 `build/ext_norm.py` 에서 만든 것입니다. **손으로 고치지 않습니다**(고치려면 `build/ext_norm.py` 를 고치고 이 도구를 다시 실행).
> 약사 검수 전 초안의 규칙입니다. 규칙이 같은 성분으로 묶은 것이 실제로 맞는지는 판정 시트(`data/review/`)로 확인합니다.

## 1. 무엇을 하는 규칙인가

심평원 약가마스터의 **영문 일반명**(예: `omeprazole sodium`)을 RxNorm 성분명(IN, 예: `omeprazole`)과 맞춥니다. 추측하지 않고 **규칙으로 같아진 이름만** 연결하며, 못 맞추면 미매핑(등급 d)으로 남깁니다. `candidates()` 는 아래 순서로 (키, 규칙 이름) 목록을 만들고, 앞쪽에서 RxNorm 이름과 처음 일치한 것으로 연결합니다.

## 2. 후보를 만드는 순서 (구체적 → 덜 구체적)

| 순서 | 규칙 | 하는 일 | 예 (입력 ⇒ 후보[규칙]) |
|---|---|---|---|
| 1 | `exact` | 소문자·공백만 정리 | `Omeprazole` ⇒ `omeprazole`[exact] |
| 2 | `moiety` | "(as X)" 표기의 X 를 본체로 봄 | `Eperisone (as eperisone hydrochloride)` ⇒ `eperisone (as eperisone hydrochloride)`[exact] → `eperisone hydrochloride`[moiety] → `eperisone`[clean] |
| 3 | `clean` | 약어 풀기(HCl→hydrochloride 등) · 괄호·농도·잡단어 제거 · 수화물 말 떼기 | `Atenolol HCl` ⇒ `atenolol hcl`[exact] → `atenolol hydrochloride`[clean] → `atenolol`[desalt]<br>`Amoxicillin Trihydrate` ⇒ `amoxicillin trihydrate`[exact] → `amoxicillin`[clean] |
| 4 | `desalt` | 염·에스테르 꼬리를 뒤에서부터 하나씩 떼기 · 중간에 낀 염 떼기 · 선두 d-/l-/dl- 떼기(마지막 수단) | `Metformin Hydrochloride` ⇒ `metformin hydrochloride`[exact] → `metformin`[desalt]<br>`Esomeprazole Magnesium Trihydrate` ⇒ `esomeprazole magnesium trihydrate`[exact] → `esomeprazole magnesium`[clean] → `esomeprazole`[desalt]<br>`L-carnitine` ⇒ `l-carnitine`[exact] → `carnitine`[desalt] |
| 5 | `decat` | 선두의 양이온(sodium·potassium·calcium·magnesium·lithium·ammonium) 떼기 | `Sodium Chondroitin Sulfate` ⇒ `sodium chondroitin sulfate`[exact] → `sodium chondroitin`[desalt] → `chondroitin sulfate`[decat] → `chondroitin`[decat] |

**짝이온만 남으면 떼지 않습니다**(성분 본체가 아니라서 잘못 연결될 수 있음):

- `Calcium Carbonate` ⇒ `calcium carbonate`[exact]
- `Sodium Chloride` ⇒ `sodium chloride`[exact]

연결 경로 중 **약한 것**(`syn/`·`desalt/`·`decat/`)은 ATC 대분류(앞 3자리)가 양쪽에서 전혀 맞지 않으면 등급 c(후보)로 내려 연결에 쓰지 않습니다. ATC 코드가 서로 달라도 그 자체가 오류의 증거는 아닙니다(WHO 가 분류를 옮긴 경우가 있음).

## 4. 규칙별 실제 사용 건수

`data/medterm_ext.json`(v1.3.0)의 `map.rule` 기준입니다. 한 성분에 이름이 여럿이면 가장 많이 쓰인 규칙 하나만 셉니다. `/IN`·`/PIN` 은 RxNorm 의 성분(IN)·정확 성분(PIN)과 맞은 것, `syn/` 은 Wikidata 동의어를 거친 것입니다.

| 규칙/경로 | 성분 수 | 등급 a | 등급 b | 등급 c |
|---|---|---|---|---|
| `exact/IN` | 1119 | 434 | 685 | 0 |
| `exact/PIN` | 413 | 213 | 200 | 0 |
| `moiety/IN` | 217 | 113 | 104 | 0 |
| `syn/exact/IN` | 103 | 25 | 78 | 0 |
| `clean/IN` | 66 | 25 | 41 | 0 |
| `desalt/IN` | 65 | 17 | 48 | 0 |
| `clean/PIN` | 62 | 15 | 47 | 0 |
| `syn/exact/PIN` | 52 | 18 | 34 | 0 |
| `syn/desalt/IN` | 20 | 3 | 17 | 0 |
| `syn/clean/IN` | 8 | 3 | 5 | 0 |
| `decat/IN` | 7 | 1 | 6 | 0 |
| `syn/clean/PIN` | 7 | 0 | 7 | 0 |
| `syn/moiety/IN` | 6 | 4 | 2 | 0 |

등급 a = 이름 일치 + ATC 7자리 일치, b = 이름 일치(ATC 근거가 한쪽에 없거나 4단계까지만 일치), c = 후보(연결에 쓰지 않음). **b 의 연결이 실제로 맞는지**가 약사 판정 시트의 핵심 질문입니다.

## 5. 알려진 한계

- 염이 달라도 같은 약으로 묶습니다(본체가 같은 성분이라는 가정). 염에 따라 약이 달라지는 드문 경우는 규칙으로 가려내지 못합니다.
- 표기가 전혀 다른 이름(약어·상품명·철자 오류)은 맞추지 못해 미매핑으로 남습니다. 비슷한 이름은 자동으로 합치지 않고 `near` 로만 알립니다.
- 한글 이름은 이 규칙표로 연결하지 않습니다(연결은 영문 일반명으로만).
