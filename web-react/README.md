# MedTerm-KR React 화면 (web-react)

화면(큰 화면은 분류 트리 · 작업 탭 · 상세의 3단, 휴대폰은 한 줄 화면 + 하단 탭)을 **React 18 · Tailwind CSS 3 · React Flow(@xyflow/react 12)** 로 만든 소스입니다. 사전 데이터와 검증 로직(`../web/js/` 의 `medterm-data.js` · `bench.js` · `core.js`)은 그대로 쓰고 **화면만** 바꿨습니다. 정보 제공용이며 진단·처방·개인별 복용량 판단에 쓰지 않습니다(버전 표기와 리서치용 LLM 질의는 아래 "실사용판 표기와 리서치용 LLM 질의" 참고).

## 결과물 (빌드하면 `dist/`에 생김 — 미리 만든 것도 함께 들어 있음)
| 파일 | 용도 |
|---|---|
| `MedTerm-KR_react.html` | 독립 실행. 더블클릭으로 열림(서버 불필요, 외부 요청 없음). 글꼴(Pretendard)은 파일 안에 담김. |
| `artifact.html` | 공유 페이지(웹 게시)용 조각: doctype·html·head·body 없음, 글꼴은 안에 담김(외부 글꼴 서버 접속 없음), 서버 프록시 입력 숨김. |
| `MedTerm-KR_app.html` | 설치형 안드로이드 앱(`../android-app`)용: 문서 전체, 외부 요청 없음(글꼴은 안에 담김), 서버 프록시 입력 숨김. 앱의 `assets/index.html` 로 복사해서 씁니다. |
| `pwa/` | **설치형 웹앱(PWA)** 폴더: `index.html`(독립 실행 화면에 설치용 태그만 더한 것) · `manifest.webmanifest` · `sw.js`(오프라인용 서비스 워커) · `icons/` · `.nojekyll`. 폴더째 https 서버의 어느 경로에 올려도 됩니다(경로가 모두 상대 경로). 아래 "웹앱(PWA)" 참고. |

`dist/tokens.css` · `dist/tw.css` 는 빌드 중간 산물이라 저장소에는 올리지 않습니다(`.gitignore`).

## 다시 만들기 (Node 22에서 확인)
```
cd web-react
npm ci
npm run build          # node build.mjs → dist/ 세 HTML + dist/pwa/ (웹앱 폴더)
```
`build.mjs` 는 기본으로 한 단계 위의 `../web/js` 를 읽습니다. 다른 폴더를 쓰려면 `MEDTERM_JS=<폴더> npm run build`.

## 웹앱(PWA)
같은 화면을 휴대폰·PC의 홈 화면/앱 목록에 설치하고, 인터넷이 끊겨도 열리게 한 판입니다(`dist/pwa/`).
- **열어 보기(내 PC)**: `python3 -m http.server 8080 --directory dist/pwa` 를 실행하고 크롬에서 `http://localhost:8080/` 를 엽니다. 주소창 오른쪽의 설치 아이콘(또는 메뉴 → 앱 설치)으로 설치합니다.
- **https 또는 localhost 에서만** 서비스 워커가 동작합니다. 같은 와이파이의 PC 주소(`http://192.168…`)로 휴대폰에서 열면 화면은 보이지만 설치·오프라인은 되지 않습니다. 휴대폰에 설치하려면 https 주소가 필요합니다.
- **오프라인**: 첫 방문 때 화면(사전 포함 `index.html` 한 파일)·설치 정보·아이콘 4개, 모두 6개 파일을 기기에 보관합니다. 이후에는 인터넷 없이 열리고, 열 때마다 뒤에서 새 판을 받아 두었다가 다음에 엽니다. 서비스 워커는 같은 주소의 GET 요청만 다루므로 서버 프록시(LLM 호출) 요청은 건드리지 않습니다.
- **새 판 반영**: 서비스 워커 파일의 버전이 화면·설치 정보·아이콘 내용의 해시(10자리)로 자동 정해집니다. 내용이 바뀌면 새 보관함이 만들어지고 옛 보관함은 지워집니다.
- **아이콘**: `pwa/icon.svg`(틸 바탕의 알약 — 안드로이드 앱 아이콘과 같은 모양) → `npm run icons`(크로미엄으로 PNG 4종 생성) → `pwa/icons/`. 모양을 바꿀 때만 다시 만들면 됩니다.
- 이 폴더를 어디에 올릴지(공개 주소)는 아직 정해지지 않았습니다. 비공개 저장소의 GitHub Pages 는 사이트가 **공개**되므로 정하기 전에는 켜지 않습니다.

### 실제 브라우저 점검 결과 (v1.2.1, 2026-11-05)
- **방법**: Playwright 로 실제 Chromium 을 열어 휴대폰 320×640·390×844, 태블릿 768, 데스크톱 1280 에서 밝은·어두운 화면, 5개 탭과 서랍·시트·분류 트리 서랍을 직접 조작하고 axe-core 로 접근성 규칙을 검사했습니다. 이 작업에는 Playwright MCP 가 연결되어 있지 않아 같은 Playwright 라이브러리를 직접 썼고, Figma MCP 로 하려던 템플릿 대조는 템플릿 파일의 편집 권한이 없고 내 파일은 무료 플랜 호출 한도에 걸려 하지 못했습니다(플랜은 바꾸지 않음).

## 실사용판 표기와 리서치용 LLM 질의 (2026-11-04)
- **"프로토타입" 표기를 없앴습니다.** 상단 제목 옆은 버전(현재 `v1.2.1`), 맨 위 안내는 "약무용어 정보 제공용입니다. …", 사전 설명문(`data/medterm.json` 의 `meta.notice`)·설치 정보·문서 제목에서도 뺐습니다. 안전 안내(진단·처방·개인별 복용량 판단 안 함 · 한글명·상품명은 약사 검수 전 초안 · 수록 성분 수 · "사전에 없음 = 확인 필요")는 그대로입니다. 검색 첫 화면에는 수록 개수 옆에 자료 기준일이 보입니다.
- **버전은 한 곳**에서 정합니다: `package.json` 의 `version` → 화면 상단. 안드로이드 `versionName` 은 같은 값으로 맞추고, `tests/app_html.cjs` 가 둘이 같은지와 앱에 담긴 화면이 이번 빌드와 같은지 확인합니다.
- **"근거 기반 질의"는 리서치용**입니다. 탭 맨 위에 "리서치용" 안내(LLM 답변은 틀릴 수 있고 임상 판단·복약 안내에 쓰지 않음)가 항상 보이고, 질의문은 `src/lib/researchPrompt.js` 의 **리서치 질의 형식(R1)** 으로 만들어집니다.
  - system: 사전 근거(항목 ID 표기)와 사전 밖 내용(출처 필수, 못 대면 "확인 필요")을 구분하게 하고, 단위용량은 미국 RxNorm 기준·한글명은 검수 전 초안임을 밝히게 하며, 진단·처방·개인별 복용량·상호작용·금기·병용·복약 안내는 "임상 판단 범위 — 이 조사에서 다루지 않음"으로 제외시킵니다. 답변은 요약 · 사전 근거로 확인된 사실 · 사전 밖 일반 지식 · 확인 필요·한계 · 추가로 확인할 자료의 5단으로 쓰게 합니다.
  - user: `<조사정보>`(형식 이름·용도·자료 기준일·RxNav 버전·수록 성분 수·출처·필드 설명) → `<사전근거>`(질문에서 찾은 성분의 JSON, 없으면 없다는 문장) → `<조사질문>`.
  - 사전 검색·답변 검증(`core.js`)은 그대로입니다. CLI `node bin/medterm.mjs prompt` 와 옛 `web/` 화면은 이전 질의 형식(`buildGroundedPrompt`)을 그대로 씁니다(`experiments/` 의 파일럿 기록과 맞추기 위해).
  - 돌아온 답변은 같은 탭의 "LLM 답변 검증"에서 사전과 대조합니다. 사전 밖 일반 지식에 나온 약물 이름은 "확인 필요"로 표시되며, "불일치 없음"은 정확하다는 보증이 아닙니다.

## 확장 수록 (v1.1.0, 2026-11-04)
핵심 사전(성분 32개, 제형·제품까지)은 그대로 두고, 공개 자료를 자동으로 모아 연결한 **성분 3,526개**(+핵심과 겹치는 32개)를 곁에 두었습니다. 자료의 구조·출처·이용 조건·다시 만드는 법: `../data/README.md`. **전부 약사 검수 전 초안**이며 허가·급여·처방 판단의 근거가 아닙니다.
- **불러오는 방법**: `../web/js/medterm-ext-data.js`(`window.MEDTERM_EXT`)가 있으면 `build.mjs` 가 HTML 에 담고, `lib/mt.js` 가 `new MedTerm(data, classes, ext)` 로 `core.js` 에 넘깁니다. 파일이 없거나 이상하면 핵심 사전만으로 이전과 똑같이 동작합니다(`../tests/ext_api.js` 가 확인).
- **검색 첫 화면**: 핵심 12개 + "더 보기"는 그대로이고, 바로 아래 안내 카드(`#ext-hint`)가 확장 수록의 개수와 "약사 검수 전"임을 알립니다. 검색어를 넣거나 ATC 대분류 칩을 고르면 핵심 결과 아래에 **"확장 수록" 목록**(24개씩 더 보기; 검색어가 있으면 점수 순, 칩만 고르면 한글 이름이 있는 성분 먼저)이 따로 나옵니다. 핵심 성분이 확장 쪽의 상품명·별칭으로 찾아지면 핵심 목록에 합쳐지고 이유에 "확장 자료 · …"가 붙습니다. 분류 칩의 숫자는 핵심 + 확장입니다(분류에 핵심 성분이 없어도, 예: ACE 억제제·베타차단제, 확장 쪽 성분이 나옵니다).
- **상세**: 확장 성분은 `ExtDetail`(한글 이름 후보와 근거 · 영문 이름 · ATC 경로 · 상품명 후보 · 국내 등재 현황 · 연결 등급 · 이름이 비슷한 항목), 핵심 성분에는 `CoreExtBlock`(국내 등재 현황만 덧붙임)이 붙습니다. 주소: 확장 성분 `#v-<RxCUI>` · `#k-<이름>`.
- **관계 그래프**: 확장 성분은 성분 · ATC · 세부군 · 같은 세부군 성분(핵심 먼저)만 그립니다. 제형(VMP)·제품(AMP)은 자료가 없어 그리지 않으며 그래프 아래에 그렇게 적습니다.
- **답변 검증**: 확장 이름이 나오면 "확장 수록 일치"로만 표시하고(사전 밖으로 걸지 않음), ATC·계열이 다르면 오류가 아니라 **경고**, 단위용량 검사는 하지 않습니다. 같은 한글 이름이 둘 이상의 확장 성분에 걸리면 어느 성분인지 정할 수 없어 일치로 쓰지 않습니다. 핵심 성분은 이전과 똑같이 오류로 판정합니다.
- **근거 기반 질의**: 질문에서 확장 성분이 찾아지면 질의문의 사전근거에 `tier: "ext"` 항목(후보 이름 · 상품명 ≤5 · ATC · 국내 등재 요약)이 들어가고, system 에 "확장 수록 자료 기준이라고 밝힐 것"이라는 규칙이 하나 더 붙습니다. 확장 성분이 없는 질문의 질의문은 이전(R1)과 같습니다.
- **정보 탭**: 확장 수록의 건수·연결 등급·출처와 이용 조건·한계를 데이터 파일(`meta`)에서 그대로 읽어 보여 줍니다. 벤치마크 숫자는 핵심 사전만으로 잰 값이며 확장 수록 상태의 성능이 아님을 밝히고, `../tests/ext_benchmark.js` 의 비교 결과를 설명합니다.
- **`core.js` 확장 API**: `searchExt(q, {classes})` → `[{ext, vtm|null, score, via}]`(이름 100 · 앞부분 80 · 포함 60 · 상품명 −1 · 별칭 −2 · ATC 접두 70(3글자 이상) · RxCUI 95 · ID 95; 이름 검색은 2글자 이상) · `describeExt(id)` · `anyById` · `hasId` · `nameOfId` · `graph(id)`(확장 중심 지원) · `verify`·`retrieve`·`contextFor`·`buildGroundedPrompt`(확장 항목은 `tier:"ext"`). 확장 자료를 주지 않으면 이전과 같은 값을 돌려줍니다.
- **출처 표기(v1.2.0)**: `SourceFooter.jsx` 가 모든 탭 맨 아래에 출처 이름 · "원 기관이 보증하지 않으며 최신이 아닐 수 있고 한글명·상품명은 약사 검수 전 초안" · ATC·SNOMED CT 재배포 미확인 · 미국 NLM 영문 표기 문구(원문 그대로, NLM 이름·로고는 쓰지 않음)를 보이고, 손가락 크기(44px 이상) "출처·이용 조건 자세히" 버튼이 정보 탭의 "출처 표기와 이용 조건" 카드(`AboutTab.jsx` 의 `AttributionSection`: NLM 문구와 한국어 풀이 · 심평원 공공누리 제1유형 문장 · Wikidata CC0 · 재배포 미결정 · 출처별 항목 수)로 보냅니다(`App.jsx` 의 `openSources` 가 위쪽 고정 탭 줄만큼 비켜서 멈춤). 확장 성분 상세에는 `ExtParts.jsx` 의 `ProvenanceBlock`(출처별 식별자·원자료 링크[새 탭, `noopener noreferrer`]·이용 조건 배지·자료 기준일과 받은 날·검수 상태)이 붙고, 핵심 성분에는 `CoreExtBlock` 안에 들어갑니다. 문구와 숫자는 모두 `core.js` 의 `attribution()` · `provenance(id)` · `provenanceStats()` 에서 오며 화면 소스에 베끼지 않습니다. 확장 자료 없이 빌드하면 RxNorm 문구만 나옵니다. `role="note"` 는 맨 위 면책 안내 하나뿐이고 출처 표기는 이름 붙은 영역(`aria-label="자료 출처 표기"`)입니다. 문구는 법률 검토를 거치지 않았고 NLM 이용 약관의 재배포 범위는 확인하지 못했습니다. 시험: `tests/ui.cjs` 19번 묶음.

## 알려진 한계
- 사전은 **핵심 성분 32개 + 확장 수록 3,526개**(이름·ATC·국내 등재 현황만)입니다. "사전에 없음"(핵심·확장 어디에도 없음)은 환각의 증거가 아니라 *확인 필요* 신호이고, "불일치 없음"은 정확하다는 뜻이 아닙니다. 한글명·상품명은 모두 약사 검수 전 초안입니다.
