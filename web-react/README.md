# MedTerm-KR React 화면 (web-react)

화면(큰 화면은 분류 트리 · 작업 탭 · 상세의 3단, 휴대폰은 한 줄 화면 + 하단 탭, 탭 8개)을 **React 18 · Tailwind CSS 3 · React Flow(@xyflow/react 12)** 로 만든 소스입니다. 사전 데이터와 검증 로직(`../web/js/` 의 `medterm-data.js` · `bench.js` · `core.js`)은 그대로 쓰고 **화면만** 바꿨습니다. 정보 제공용이며 진단·처방·개인별 복용량 판단에 쓰지 않습니다(버전 표기와 리서치용 LLM 질의는 아래 "실사용판 표기와 리서치용 LLM 질의" 참고).

## 결과물 (빌드하면 `dist/`에 생김 — 미리 만든 것도 함께 들어 있음)
| 파일 | 용도 |
|---|---|
| `MedTerm-KR_react.html` | 독립 실행. 더블클릭으로 열림(서버 불필요, 외부 요청 없음 — 단, 운영자가 보내기 주소를 넣어 빌드한 판은 ‘MedIT로 보내기’를 누를 때만 요청 1건). 글꼴(Pretendard)은 파일 안에 담김. |
| `artifact.html` | 공유 페이지(웹 게시)용 조각: doctype·html·head·body 없음, 글꼴은 안에 담김(외부 글꼴 서버 접속 없음), 서버 프록시 입력 숨김. |
| `MedTerm-KR_app.html` | 설치형 안드로이드 앱(`../android-app`)용: 문서 전체, 외부 요청 없음(글꼴은 안에 담김), 서버 프록시 입력 숨김. 앱의 `assets/index.html` 로 복사해서 씁니다. |
| `pwa/` | **설치형 웹앱(PWA)** 폴더: `index.html`(독립 실행 화면에 설치용 태그만 더한 것) · `manifest.webmanifest` · `sw.js`(오프라인용 서비스 워커) · `icons/` · `.nojekyll`. 폴더째 https 서버의 어느 경로에 올려도 됩니다(경로가 모두 상대 경로). 아래 "웹앱(PWA)" 참고. |
| `MedTerm-KR_showcase.html` | **웹 + 모바일 앱 나란히 보기**(v1.4.0): 독립 실행 한 파일(약 13 MB, 서버 불필요, 외부 요청 없음). 큰 화면은 왼쪽 웹 화면 + 오른쪽 휴대폰 틀 안의 앱 화면, 휴대폰은 앱 화면만 바로 열림. 아래 "웹앱 + 모바일 앱 나란히 보기" 참고. |
| `showcase_artifact.html` | 위와 같은 화면의 공유 페이지(웹 게시)용 조각: doctype·html·head·body 없음, 16 MB 한도 안(빌드가 15.5 MB 를 넘으면 실패). |

`dist/tokens.css` · `dist/tw.css` 는 빌드 중간 산물이라 저장소에는 올리지 않습니다(`.gitignore`).

## 다시 만들기 (Node 22에서 확인)
```
cd web-react
npm ci
npm run build          # node build.mjs → dist/ HTML 5개(독립 실행·공유 페이지·설치형 앱·나란히 보기 2종) + dist/pwa/ (웹앱 폴더)
```
`build.mjs` 는 기본으로 한 단계 위의 `../web/js` 를 읽습니다. 다른 폴더를 쓰려면 `MEDTERM_JS=<폴더> npm run build`.

## 웹앱(PWA)
같은 화면을 휴대폰·PC의 홈 화면/앱 목록에 설치하고, 인터넷이 끊겨도 열리게 한 판입니다(`dist/pwa/`).
- **열어 보기(내 PC)**: `python3 -m http.server 8080 --directory dist/pwa` 를 실행하고 크롬에서 `http://localhost:8080/` 를 엽니다. 주소창 오른쪽의 설치 아이콘(또는 메뉴 → 앱 설치)으로 설치합니다.
- **https 또는 localhost 에서만** 서비스 워커가 동작합니다. 같은 와이파이의 PC 주소(`http://192.168…`)로 휴대폰에서 열면 화면은 보이지만 설치·오프라인은 되지 않습니다. 휴대폰에 설치하려면 https 주소가 필요합니다.
- **오프라인**: 첫 방문 때 화면(사전 포함 `index.html` 한 파일)·설치 정보·아이콘 4개, 모두 6개 파일을 기기에 보관합니다. 이후에는 인터넷 없이 열리고, 열 때마다 뒤에서 새 판을 받아 두었다가 다음에 엽니다. 서비스 워커는 같은 주소의 GET 요청만 다루므로 서버 프록시(LLM 호출)·‘MedIT로 보내기’ 요청은 건드리지 않습니다.
- **새 판 반영**: 서비스 워커 파일의 버전이 화면·설치 정보·아이콘 내용의 해시(10자리)로 자동 정해집니다. 내용이 바뀌면 새 보관함이 만들어지고 옛 보관함은 지워집니다.
- **아이콘**: `pwa/icon.svg`(틸 바탕의 알약 — 안드로이드 앱 아이콘과 같은 모양) → `npm run icons`(크로미엄으로 PNG 4종 생성) → `pwa/icons/`. 모양을 바꿀 때만 다시 만들면 됩니다.
- 이 폴더를 어디에 올릴지(공개 주소)는 아직 정해지지 않았습니다. 비공개 저장소의 GitHub Pages 는 사이트가 **공개**되므로 정하기 전에는 켜지 않습니다.

### 실제 브라우저 점검 결과 (v1.2.1, 2026-11-05)
- **방법**: Playwright 로 실제 Chromium 을 열어 휴대폰 320×640·390×844, 태블릿 768, 데스크톱 1280 에서 밝은·어두운 화면, 5개 탭과 서랍·시트·분류 트리 서랍을 직접 조작하고 axe-core 로 접근성 규칙을 검사했습니다. 이 작업에는 Playwright MCP 가 연결되어 있지 않아 같은 Playwright 라이브러리를 직접 썼고, Figma MCP 로 하려던 템플릿 대조는 템플릿 파일의 편집 권한이 없고 내 파일은 무료 플랜 호출 한도에 걸려 하지 못했습니다(플랜은 바꾸지 않음).
- **고친 것**: ① 휴대폰에서 검색어를 입력해도 결과가 큰 안내 카드(제목·그림·예시·도움말) 아래로 밀려 첫 화면에 보이지 않던 문제(검색어가 있으면 안내 카드를 접어, 320×640 에서 첫 결과 카드가 위에서 334–463px 에 놓여 하단 탭 줄 윗선(577px)보다 위에 보임) ② 그래프 탭 안내의 방향 말("왼쪽 트리")이 휴대폰에서는 맞지 않던 문구 ③ axe 위반: 머리글 밖에 있던 안내문·하단 탭이 `region` 밖, `h3` 로 건너뛴 제목 순서, `aside` 에 `role=dialog`, 좁은 화면에서 옆으로 밀리는 근거 표를 키보드로 못 미는 문제, 답변 검증 탭에 제목 없음 ④ 누르는 면: 터치 화면과 휴대폰 폭에서 44px 이상(예시 칩·서랍 줄·트리 줄·그래프 도구줄·출처 링크 등), 마우스 화면은 24px 이상, 그래프 오른쪽 아래 출처 링크도 24px 이상 ⑤ 전체 초점 링 2px.

## 실사용판 표기와 리서치용 LLM 질의 (2026-11-04)
- **"프로토타입" 표기를 없앴습니다.** 상단 제목 옆은 버전(현재 `v1.6.0`), 맨 위 안내는 "약무용어 정보 제공용입니다. …", 사전 설명문(`data/medterm.json` 의 `meta.notice`)·설치 정보·문서 제목에서도 뺐습니다. 안전 안내(진단·처방·개인별 복용량 판단 안 함 · 한글명·상품명은 약사 검수 전 초안 · 수록 성분 수 · "사전에 없음 = 확인 필요")는 그대로입니다. 검색 첫 화면에는 수록 개수 옆에 자료 기준일이 보입니다.
- **버전은 한 곳**에서 정합니다: `package.json` 의 `version` → 화면 상단. 안드로이드 `versionName` 은 같은 값으로 맞추고, `tests/app_html.cjs` 가 둘이 같은지와 앱에 담긴 화면이 이번 빌드와 같은지 확인합니다.
- **"근거 기반 질의"는 리서치용**입니다. 탭 맨 위에 "리서치용" 안내(LLM 답변은 틀릴 수 있고 임상 판단·복약 안내에 쓰지 않음)가 항상 보이고, 질의문은 `src/lib/researchPrompt.js` 의 **리서치 질의 형식(R1)** 으로 만들어집니다.
  - system: 사전 근거(항목 ID 표기)와 사전 밖 내용(출처 필수, 못 대면 "확인 필요")을 구분하게 하고, 단위용량은 미국 RxNorm 기준·한글명은 검수 전 초안임을 밝히게 하며, 진단·처방·개인별 복용량·상호작용·금기·병용·복약 안내는 "임상 판단 범위 — 이 조사에서 다루지 않음"으로 제외시킵니다. 답변은 요약 · 사전 근거로 확인된 사실 · 사전 밖 일반 지식 · 확인 필요·한계 · 추가로 확인할 자료의 5단으로 쓰게 합니다.
  - user: `<조사정보>`(형식 이름·용도·자료 기준일·RxNav 버전·수록 성분 수·출처·필드 설명) → `<사전근거>`(질문에서 찾은 성분의 JSON, 없으면 없다는 문장) → `<조사질문>`.
  - 사전 검색·답변 검증(`core.js`)은 그대로입니다. CLI `node bin/medterm.mjs prompt` 와 옛 `web/` 화면은 이전 질의 형식(`buildGroundedPrompt`)을 그대로 씁니다(`experiments/` 의 파일럿 기록과 맞추기 위해).
  - 돌아온 답변은 같은 탭의 "LLM 답변 검증"에서 사전과 대조합니다. 사전 밖 일반 지식에 나온 약물 이름은 "확인 필요"로 표시되며, "불일치 없음"은 정확하다는 보증이 아닙니다.
  - 예전 "시연용 답변 넣기(오프라인 데모)" 버튼은 "예시 답변 넣기(오류 포함)"로 이름을 바꿨습니다.

## 검수 상태 표시와 공개용 축소판 (v1.4.1, 2026-11-06)
**한글명·상품명·약사법 쉬운 풀이를 공식 자료와 대조**하고, 그 범위를 화면에 적었습니다. 이것은 자료끼리의 대조이며 **약사의 검수가 아니므로** "약사 검수 전" 표시는 그대로입니다(대조 내용·도구: `../data/README.md` 의 "한글명·상품명·약사법 풀이 대조").
- **데이터·한계 탭 ‘검수 상태’ 절**(`#about-review`, `AboutTab.jsx` 의 `ReviewSection`): 공식 자료와 대조한 것(핵심 성분 한글명 32개 · 핵심 국내 상품명 28개 · 약사법 쉬운 풀이 53개)과 아직 하지 못한 것(약사 자격자의 검수 · 약사법 현행 시행본 대조 · 시행령·시행규칙 · 식약처 대조 · 제형 한글명·계열명·확장 수록·제품 연결)을 적습니다. 약사법·확장·제품 줄은 **그 자료 층이 있는 판에서만** 나옵니다(핵심만 있는 판의 정보 탭에는 "확장" 글자가 없어야 하는 기존 점검을 지키기 위함).
- **약무·제도 탭 머리글**: 풀이가 출력본과 항목별로 대조되었다는 문장(`pl_checked`), 출력본에 시행일이 서로 다른 규정이 함께 실려 있다는 설명, 그리고 2026-11-06 에 본 국가법령정보센터 현행 표시(시행 2026-10-08, 법률 제21525호)를 **대조하지 못했다**는 문장이 들어갑니다.
- **공개용 축소판(lite)**: 외부 주소(GitHub Pages 등)에 올릴 때 쓰는 판입니다. SNOMED CT 식별자 · ATC 영문 분류 이름 · RxClass 에서만 온 ATC 값을 뺀 자료로 만들고(`../build/make_lite.py`), 검색 로봇이 색인하지 않도록 `noindex` 를 넣습니다(`MEDTERM_EDITION=lite`). 원본 `data/` 와 `dist/` 는 건드리지 않고 다른 폴더에 만듭니다:
  ```
  python3 ../build/make_lite.py --out <폴더>
  MEDTERM_JS=<폴더>/js MEDTERM_DIST=<폴더>/dist MEDTERM_EDITION=lite node build.mjs
  MEDTERM_DIST=<폴더>/dist node tests/lite.cjs      # 공개판 점검(빠진 값이 파일 어디에도 남아 있지 않은지 포함)
  ```
  공개판의 `LITE` 표시(`src/lib/edition.js`)가 켜지면 위쪽 제목 옆에 "공개 미리보기(초안)"가 붙고, 정보 탭과 하단 출처 표기가 "이 공개판에는 SNOMED CT ID와 ATC 영문 분류명을 넣지 않았습니다"로 바뀝니다. 심평원(공공누리 제1유형)·Wikidata(CC0)에서 온 **ATC 코드 값**은 남겼으며, 코드 값 자체의 공개 범위는 아직 결정하지 않았습니다. 공개판도 모든 한글명·상품명·풀이는 약사 검수 전입니다.
